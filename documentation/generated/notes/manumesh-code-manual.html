QEM 二次型展开速查：当前到底加了哪些项

ManuMesh 当前把所有软几何成本统一累积到齐次二次型。设 x 是候选新顶点位置，x_h=[x,1]^T，每个顶点保存 Q=[[A,b],[b^T,c]]，则候选代价为 E(x)=x_h^T Q x_h=x^T A x+2 b^T x+c。折叠边 (i,j) 时先做 Q_edge=Q_i+Q_j，再解 A x=-b；若矩阵病态则回退到端点/中点候选。

二次型项展开到 A,b,c参数与默认值作用与引用
面平面 QEMpi=[n,-n.p]，Q += area/3 * pi*pi^T。等价于 E=a(n.x-n.p)^2，所以 A+=a nn^T、b+=-a(n.p)n、c+=a(n.p)^2。无独立开关；退化面使用 1e-6 * representativeArea * pointQuadric，保持与正常 QEM 相同的 L^4 缩放量纲。主几何误差，来自 M002 Garland-Heckbert 1997。
普通 Line QuadriclineQuadric(p,n) 取两个与局部法线 n 垂直的单位方向 u,v，加入 Q_l=pi_u*pi_u^T+pi_v*pi_v^T。展开为 E_l=||(I-nn^T)(x-p)||^2，即惩罚切向漂移。useLineQuadrics=true，lineWeight=1e-3。默认分支：Q_i += w_i area_i Q_l。补平坦区 QEM 切向不满秩问题，来自 M004 Liu-Rahimzadeh-Zordan 2025。
特征加权 Line Quadric非 uniform 模式下 w_i=lineWeight+featureBoost*s_i；s_i 来自 dihedral、normal-tensor persistence、height 或 xband。normal-tensor 模式只给满足 normalTensorMinPersistentScales 的顶点写入 persistent score。weightMode=uniform，featureBoost=0.05；常用调试值 dihedral/normal-tensor + 0.08。featureAngleDeg=40，normalTensorFeatureThreshold=0.16，normalTensorScaleCount=1。让硬边、弱 ridge 或指定区域获得更高排序成本；feature evidence 参考 M007/M012/M013/M015/M016，弱特征参考 M026。
Adaptive Scale 分支若 adaptiveScale=true，当前实现给 placement 只加干净的 adaptiveBaseLineWeight*area_i*Q_l；featureBoost 不再缩放 Q_i，而是写成逐顶点队列优先级因子 priorityScale=1+max(0,featureBoost)*s_i，候选边取两端点的 max，只乘在排序 cost 上（Wang 2008 的“优先级/位置解耦”）。adaptiveScale=false，adaptiveBaseLineWeight=1e-2。非 adaptiveScale 路径保持旧的 w_i=lineWeight+featureBoost*s_i 行为。用于跨尺度模型的 line weight 可比性，同时避免 featureBoost 污染 placement 求解；参考 M029 Wang 2008。
边界 Plane Quadric边界边 (a,b) 只有一个邻接面时，取 m=normalize(n_face x e_hat)，加入 Q_b=boundaryWeight*|e|^2*pi_m*pi_m^T 到两个端点。它的 A=boundaryWeight*|e|^2*mm^T，秩 1；边长平方使该项与面积加权 face QEM 同为 L^4 缩放量纲。boundaryWeight=0.0 默认关闭；常用 1-10。硬边界保护另看 preserveBoundary。减少开放边界沿面内法向漂移；扩展 QEM 思路参考 M003，工程 guards 参考 M030-M033。
特征曲线 Tangent-Line Quadric当检测到 loop/primitive 后，对特征顶点用切线 t 调用 lineQuadric(p,t)，即 E_curve=eta*rho*area*||(I-tt^T)(x-p)||^2。这里 rho=0.35+0.65*confidence。preserveFeatureCurves=false 默认关闭；featureCurveWeight=0.05，常用 0.08；featureComponentMinConfidence=0.35 只影响 high-confidence component 报告计数，不过滤 component 或保护。允许沿特征线滑动，惩罚离开曲线；组合 M004 line quadrics、M016 CAD feature line、M026 weak-feature consolidation、M028/M029 feature-preserving simplification。
Primitive 投影与硬过滤圆/椭圆/多边形不是当前 Quadrics.cpp 里的单独径向二次型；当前代码用 tangent-line quadric 排序，再由 projectToCircle/projectToEllipse/projectToPolygonal、maxFeatureCurveDeviationRatio 和 featureProtectionMode 控制最终位置与是否拒绝折叠。maxFeatureCurveDeviationRatio=0 表示关闭曲线漂移预算；featureProtectionMode=PrimitiveCurves。圆/椭圆阈值默认均为 0.05。把“软成本排序”和“硬合法性保护”分开，符合 M030-M033 edge-collapse 工程建议。

为什么识别到边界、dihedral 或 normal-tensor 特征后要提高 Line Quadric 权重

先把一个容易误解的点说清楚：提高 lineWeight 或 featureBoost，确实会改变 A x=-b 的最小误差位置。它会让位置从“纯 plane QEM 的最优点”偏向“更靠近原顶点法线支撑线、切向漂移更小”的点。因此这不是免费的精度提升，而是一个有意加入的软正则项。M004 line quadrics 的核心价值，正是给标准 QEM 在平坦或近似平坦区域缺失的切向方向补一个小惩罚；M030-M033 的 edge-collapse 工程路线也强调，QEM/line quadrics 负责候选排序，真正危险的 collapse 仍要交给拓扑、边界、特征和质量过滤器。

当前代码里，weightMode=dihedral 会把开边界边记为 score=1，把超过 featureAngleDeg 的二面角边按强度写入端点分数；weightMode=normal-tensor 则使用满足 normalTensorMinPersistentScales 的 persistent feature score。随后普通 line quadric 的权重变成 w_i=lineWeight+featureBoost*s_i。这意味着边界、硬折痕、弱 ridge 附近的候选点，如果试图沿局部切平面大幅滑走，会在优先队列里付出更高代价。

疑问准确回答对应代码/参数
为什么识别到特征还要加 line 权重？因为 plane QEM 主要惩罚离开局部平面，很多特征破坏发生在切向：点沿表面滑过折痕、孔边被拖圆、边界轮廓缩进。Line quadric 惩罚 ||(I-nn^T)(x-p)||^2，正好给这种切向漂移加成本。Quadrics.cpp::lineQuadric，lineWeight，featureBoost
这会不会让最小误差位置更偏？会。它会偏离纯 plane QEM 的最优点，但这个偏移的方向是“少做切向漂移”。如果纯 plane QEM 本来在切向不满秩或近似不满秩，那么这个偏移反而让候选 placement 更稳定。solvePlacementCandidates() 用合并后的 Q_i+Q_j 求解
为什么特征附近要比普通平面更强？普通平面内的小滑动通常视觉影响不大；特征线附近同样大小的滑动可能跨过 CAD patch boundary、浅 ridge 或孔边。提高 w_i 让这些 collapse 排序靠后，给非特征区域优先被简化的机会。w_i=lineWeight+featureBoost*s_i
边界线也靠 line 权重保护吗？不是只靠它。开边界在 dihedral weight mode 下会得到高 feature score，从而减少切向漂移；但真正的边界形状和拓扑还要看 boundaryWeight 的边界 plane quadric、preserveBoundary 的硬策略和 topology guards。addBoundaryQuadrics()，preserveBoundary
normal tensor 弱特征会不会误检后过度保护？会有这个风险。normal-tensor 路径用 persistent score、最少支持尺度和 edge alignment 降低单尺度噪声；component confidence 在 Quadrics.cpp:195 通过 0.35 + 0.65·confidence 连续缩放软 quadric。注意 featureComponentMinConfidence 只是报告阈值，不会过滤弱特征或关闭保护。normalTensorFeatureThreshold，normalTensorMinPersistentScales，VertexFeature::confidence

可以用一个二维化的例子看直觉。假设局部平面是 z=0，纯 plane QEM 是 E_plane=2*z^2。候选点从 (10,5,0) 滑到 (11,5,0) 时，纯 plane QEM 代价仍是 0，因为它没有离开平面。加入普通 line quadric 后，代价多出 0.002；如果 normal-tensor persistent score 是 0.6 且 featureBoost=0.08，同样 1 mm 切向滑动代价变成 0.098。这并不是说几何误差突然大了 49 倍，而是系统在告诉优先队列：“这里像特征支撑，不要把切向漂移很大的 collapse 排得太靠前。”

因此正确的调参原则不是“特征越强，line 权重越大越好”。更稳的顺序是：保持基础 lineWeight 小，让它只修补平坦区病态；让 featureBoost 只放大高置信的 dihedral/normal-tensor 证据；把圆、椭圆、polygonal loop 交给 featureCurveWeight、primitive projection 和 hard feature policy；最后用 feature_rejected、generic_feature_rejected、max_orig_to_simp 和 feature drift 去判断是否过度保护。这个取舍也对应 M026 弱特征整合和 M030-M033 collapse guards 的思路：先让特征证据形成可靠 support，再决定软成本、硬保护或后处理投影。

因此当前总能量可读成：E = E_plane + E_line(weightMode) + E_boundary + E_feature_curve；拓扑、边界、特征保护、法向翻转、三角形质量、局部误差和自交检查不是二次型项，而是候选折叠通过 QEM 排序之后的硬过滤。

1这份程序实现了什么

当前仓库实现的是一个基于边坍缩的三角网格简化库。它以 Garland-Heckbert 标准 QEM 为基础，加入 Liu、Rahimzadeh、Zordan 在 SGP 2025 论文中提出的 Line Quadrics 思想，用很小的线二次型权重改善标准 QEM 在平坦区域的退化排序问题。

从工程角度看，它现在有两层使用方式：

  • 动态库：目标名 manumesh，外部 CMake 工程可以通过 find_package(ManuMesh CONFIG REQUIRED) 使用。
  • CLI 程序：目标名 manumesh，用于生成 demo 网格、简化 STL/OBJ、输出 metrics、做 sweep 实验和特征报告。
我对你原网页的判断

你给的 qem-line-quadrics-notes.html 对当前程序很有启发意义，因为它把“标准 QEM 的零误差平坦区”和“Line Quadrics 为什么能补上切向约束”讲成了同一个数学故事。当前程序的核心代码正是沿着这个故事组织的：先建立平面 quadric，再把顶点法线方向的 line quadric 作为正则项加进去。

2.3 当前程序不是论文的逐字逐句复刻

本程序复现了 Line Quadrics 对 QEM 的关键增强，但也加入了工程实验分支：

  • weightMode 提供 uniform、dihedral、normal-tensor、height、xband 五种权重模式，用来观察不同区域权重如何影响简化。
  • boundaryWeight 增加边界 plane quadric，用来缓解边界漂移。
  • preserveFeatureCurves 增加特征 loop 检测、圆拟合、最小顶点数保护和圆投影。
  • 求解器对奇异矩阵使用端点/中点 fallback 候选集，优先保证程序稳定运行。

4公共 API 与数据结构

4.1 Mesh

namespace manumesh {
using Vec2 = Eigen::Vector2d;
using Vec3 = Eigen::Vector3d;
using Mat4 = Eigen::Matrix4d;

struct Face {
  std::array<int, 3> v{};
};

struct FaceTexCoords {
  std::array<Vec2, 3> uv{};
  bool valid;
};

struct Mesh {
  std::vector<Vec3> vertices;
  std::vector<Face> faces;
  std::vector<FaceTexCoords> faceTexCoords;

  bool hasTextureCoordinates() const;
};
}

Mesh 是没有半边结构的简单三角网格容器。算法内部会临时构建边表、活动面、活动顶点、版本号和优先队列；公共 API 保持轻量，便于动态库调用。

2026-07 起 Mesh 增加了可选的纹理坐标存储 faceTexCoords。它为空表示网格没有纹理；非空时与 faces 一一对齐，个别条目可以是 invalid（对应 OBJ 中没有贴图的面）。UV 采用角拥有（corner-owned）而不是"顶点拥有"语义：每个面的三个角各自保存一份 UV，因为一个几何顶点可以同时属于多个 UV chart（纹理接缝 seam 处正是如此），顶点拥有的 UV 无法表达这种情况。hasTextureCoordinates() 在至少一个面带有效逐角坐标时返回 true。

SDK 边界上的 Eigen-free 镜像 PlainMesh（include/core/PlainMesh.h）同步增加了 PlainVec2 { double u, v; }、PlainFaceTexCoords 和 PlainMesh::faceTexCoords 字段，双向转换以及 compaction/validation/remap 都会一并处理逐角 UV。

4.3 SimplifyReport

SimplifyReport 用于观察算法行为，例如实际坍缩边数、拒绝坍缩次数、fallback 求解次数、检测到的特征 loop 数、圆形特征 loop 数、投影放置次数等。这些字段对调参很重要，因为不同输入网格的失败原因通常不在最终 STL 里，而在中间统计里。

纹理保护启用后，报告中新增两个诊断字段：textureProtectedEdges 统计初始状态下就不存在合法中点纹理坍缩的边数，textureRejectedCollapses 统计 placement 评估之后被纹理检查（chart 配对、UV 定向、面积下限）否决的队列候选数。前者衡量输入网格 seam/chart 结构本身的紧张程度，后者衡量简化过程中纹理保护的实际拦截强度。

5A.2 看不懂结果时的最短排查链

  1. 先判定是检测问题还是简化问题：只跑 feature-report，如果 loop/component/primitive 已经不对，先别调 QEM。
  2. 再分强证据和弱证据：强 CAD 边看 boundary/dihedral/non-manifold；浅 ridge 看 normal tensor score、persistence、alignment。
  3. 再看图质量：edge 多但 loop 少时，通常是 gap、spur 或 junction 问题，不是 QEM 代价问题。
  4. 必要时打开 HTML 线框：如果 CSV 指标能说明阶段但很难定位局部边，临时用 MANUMESH_DEBUG_UTIL_FEATURES 或 MANUMESH_DEBUG_UTIL_EDGES 看 feature graph / candidate edge 的空间位置。
  5. 最后看 QEM 消费：检测正确但简化后漂移，才看 feature-curve weight、primitive hard budget、line weight 和 target ratio。

6simplifyMesh 执行流程

核心流程如下：

simplifyMesh(input, options, report) 1. 如果 preserveFeatureCurves，先 detectFeatureCurves(input) 2. computeInitialQuadrics() - 面 plane quadric - 可选 boundary quadric - 可选 normal line quadric - 可选 feature tangent line quadric 3. 初始化 VertexState / FaceState 4. collectActiveEdges() 并构建优先队列 5. 循环直到 activeFaceCount <= targetFaces a. 弹出最低代价候选边 b. 检查版本号、端点活动状态、邻接关系 c. 合并端点 quadric，求解新位置（全空间最优 → 沿折叠边一维最优 → 端点/中点三级回退） d. 特征约束检查 e. 圆形特征投影 f. 退化面/合法性检查（link condition 含“边界弦”拒绝：内部边两端点均为边界顶点一律拒绝） g. 写回顶点、重写面、删除退化面和重复面 h. 把受影响邻边重新压入队列 6. compactResult() 输出 Mesh

6.1 顶点状态

内部 VertexState 不只保存位置和 quadric，还保存：

  • active：顶点是否仍存在。
  • version：优先队列 stale candidate 检查。
  • isFeature、loopId、circularFeature：特征约束。
  • curveTangent：特征曲线切线；圆/椭圆拟合参数已从 VertexState 移到 FeaturePrimitiveFit side table，顶点只保留 primitiveFitId 引用，非特征顶点不携带拟合负载。

6.2 候选边代价

对候选边 $(i,j)$，程序先合并 quadric：

$$Q_{ij}=Q_i+Q_j$$

再通过 solveOptimal 得到新位置 $x$ 和代价：

$$cost(i,j)=\bar{x}^{\top}Q_{ij}\bar{x}$$

优先队列按 cost 从小到大弹出，形成局部贪心简化。

10有没有更好的论文方法

有。当前程序的边界项和 tangent-line 特征曲线项是一个轻量、容易集成进 QEM 的方案。如果要继续往工业软件方向走，可以按目标选择更强方法。

目标更强方法代表参考对当前程序的启发
边界保持更稳约束式边坍缩：把边界、feature edge 标成 constrained edge，不允许跨越或破坏约束边。CGAL Surface Mesh Simplification 的 constrained edges / placement filter；Hoppe 1996 Progressive Meshes 中的 discontinuity curves。比单纯加 boundaryWeight 更硬。可以新增 constrainedEdges 输入，边界边默认不跨边坍缩。
边界和体积同时保持Lindstrom-Turk memoryless simplification，用体积保持、边界面积保持、三角形形状优化作为约束序列。Lindstrom and Turk, Fast and Memory Efficient Polygonal Simplification, VIS 1998。适合加一个 PlacementPolicy，在 QEM placement 之外提供体积/边界约束 placement。
特征线识别更可靠不要只靠二面角；引入 CAD 特征线、C0/C1/C2 discontinuity、normal tensor、曲率多尺度检测。Vidal-Wolf-Dupont 2011；Jiao-Bayyana 2008；Tsuchie-Higashi 2014。当前 detectFeatureCurves 可替换为更强 detector，输出仍然是 feature vertices/loops/tangents。
特征保持更强特征边硬约束 + 特征边独立简化 + 曲面区域简化，再重建/缝合。Peyrot-Payan-Antonini 2014 aliasing-free simplification；Hussain-Grahn-Persson 2008 feature-preserving simplification。比 tangent-line soft constraint 更稳定，适合 CAD 模型：先简化 feature graph，再简化 patch interior。
特征敏感误差更统一把位置和法线一起放进高维 feature-sensitive metric，或用 normal-guided QEM。Wei and Lou 2010 feature sensitive metric；Zheng et al. 2014 normal-guided QEM denoising。可以把当前 lineWeight 扩展为“位置误差 + 法线误差 + 特征距离”的组合能量。
误差有硬保证Hausdorff envelope / tolerance volume；每次坍缩必须满足误差界。Hausdorff envelope surface simplification 文献；CGAL/工程库中的 placement filter 思路。工业精度要求高时，这是比 QEM 代价更可靠的验收层。QEM 可做候选排序，Hausdorff/tolerance 做硬过滤。

12当前实现的风险与后续增强点

  • C++ ABI：C++ 公共 API 暴露 std::vector、std::string、Eigen 类型，适合同编译器/同运行时的 C++ 项目。跨语言使用应走已存在的 C ABI 包装层（include/api/CApi.h + src/api/CApi.cpp）：入口带 std::bad_alloc → OOM 状态码 guard 与数值参数 finite 校验（如 merge_relative_epsilon 须有限非负）；注意 v1 ABI 不携带逐角纹理坐标。
  • 拓扑保护：link condition、局部自交检测和“边界弦”拒绝（内部边但两端点均为边界顶点时一律拒绝坍缩，防边界 pinch 成非流形点；与 preserveBoundary 无关、始终生效）已在 CollapseTopology.cpp/CollapseLegality.cpp 落地。边界环一致性等更完整的工业拓扑证明仍是后续方向。
  • 特征检测：当前主要靠边界、二面角和圆拟合。更复杂 CAD 模型可以引入 normal tensor、曲率、多尺度特征线方法。
  • 误差度量：当前没有严格 Hausdorff 误差界。纹理坐标已经可以随简化传播并受 preserveTexture 的 chart/seam/面积保护，但法线、颜色等其他属性迁移和全局误差界认证仍是后续方向。
