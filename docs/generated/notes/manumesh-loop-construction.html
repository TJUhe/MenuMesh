1. 一句话先讲明白

当前程序里的 loop 构造不是“看到一圈边就直接闭合”。 它先把可追踪的特征边做成一个无向 `TraceGraph`，再按五个优先级恢复曲线：先抢救分叉图里的圆环，再找小型多边形 cycle，然后追踪剩余边，最后用 primitive 拟合和三点圆搜索（种子来自 trace 图长度 2 路径，并要求 cluster 由特征边基本连通）补救碎片化 CAD 环。真正落地的数据结构统一由 `FeatureLoopBuilder.cpp` 创建并写回到 `FeatureAnalysis.loops` 和 `FeatureAnalysis.vertices`。C01C05

如果只看名字，`FeatureLoop` 很容易误解成“必须闭合的环”。但代码实际更宽：它可以是闭合环，也可以是开链；可以是有真实边顺序的 trace 结果，也可以是一个被 circle/ellipse 拟合成功的顶点集合 fallback。这个设计服务于后续简化保护：只要能给顶点提供特征归属、primitive、切向方向，就能被 QEM 特征保护消费。C07C14

2. 这里的 loop 到底是什么意思

`FeatureLoop` 的字段本身说明它不是单纯的拓扑环：`closed` 表示追踪上是否闭合，`circular` 表示 primitive 分类是否为 circle/near-circle，`primitive` 还可能是 ellipse 或 polygonal loop，`mostlyBoundary` 表示证据来源大多是边界边。核心字段在 `FeatureTypes.h` 中定义。C11

概念代码含义为什么容易误解后续影响
FeatureLoop 一条恢复出来的特征曲线或特征环，包含顶点序列、边数、闭合标记、primitive 拟合结果、凸凹二面角统计。 名字叫 loop，但 `addTracedLoop` 会把开链也放进 `analysis.loops`。 后续渲染、CLI 报告、简化保护主要读这个数组。
closed 追踪或恢复算法认为首尾闭合。 闭合不等于圆。多边形边界、孔边界、椭圆都可以 closed。 只有闭合且点数足够的 traced loop 会尝试 primitive fit。
circular primitive fit 被分类为 `Circle` 或 `NearCircle`。 圆形是几何拟合结论，不是拓扑结论。 顶点会获得 circle center/normal/radius 和圆切线，用于圆形保护与投影。
primitive `Unknown`、`Circle`、`NearCircle`、`Ellipse`、`PolygonalLoop` 之一。 polygonal 也来自 primitive fit 的分类，不是单纯“没有拟合”。 `PrimitiveCurves` 保护模式会区分 circle/near-circle/ellipse/polygonal。
vertices 对 trace 得到的曲线通常是有边顺序的顶点序列；对 primitive component fallback 可能是 component 顶点集合。 并不是所有 fallback 都保证沿边顺序。 circle/ellipse fallback 更依赖 primitive 几何和顶点切线，少依赖顺序。

3. 进入 loop 构造前已经有什么

loop recovery 接收的不是原始网格边，而是 `TraceGraph`。这个图来自候选特征边 `CandidateEdge`，每条边带着 boundary、dihedral、normalTensor、smoothCurvature（opt-in 的确定性光滑曲率弱证据，本轮新增）、nonManifold、cleanupBridge、signedKind 以及 tensor/curvature persistence 等证据。C10

TraceGraph 的过滤规则

`buildTraceGraph` 里有一个关键选择：所有 boundary、non-manifold、normal tensor 和 smooth curvature 边都直接可追踪；dihedral 边必须满足 `angleRad >= loopTraceAngle`。如果 `loopTraceAngleDeg < 0`，就复用 `featureAngleDeg`；否则用更严格或更宽松的单独追踪阈值。没有进入 `TraceGraph` 的候选边仍然算 feature evidence，但不会构造 loop ownership。C02

smoothCurvature 是新的弱证据来源（opt-in）。 打开 `FeatureOptions::useSmoothCurvatureFeatures`（CLI 为 `--smooth-curvature-features`，默认关闭）后，确定性多尺度 quadric 曲率检测会把光滑 ridge/valley 的顶点证据转成 `smoothCurvature` 标记的候选边。它与 boundary/dihedral/nonManifold/normalTensor 并列进入 feature graph；一旦进图，就与其他来源在 loop 追踪与 cleanup 中同等参与——只在“弱证据”相关的保守规则（删短 spur、跳过弱证据分量的闭合 fallback）里与 normalTensor 受到相同对待。设计细节见 docs/design/smooth_curvature_feature_detection_2026_07_11.md。
这就是为什么同样检测到了 dihedral feature edge，却可能没有 loop。 测试 `ReportsUntracedDihedralEdgesWhenTraceAngleIsStricter` 把 `loopTraceAngleDeg` 设为 179 度，结果 `featureEdges == untracedFeatureEdges`，`tracedFeatureEdges == 0`，`loops.empty()`。T04

cleanup 对 loop 的影响

loop recovery 之前，`cleanupTraceGraph` 会按固定顺序删弱证据 spur、桥接近 junction、桥接 endpoint gap。bridge 共享 `FeatureGraphCompatibility`：双端 continuation、evidence source 与 ridge/valley signed kind 必须兼容；endpoint cleanup 继续要求 Yoshizawa 双端角度规则。端点超过 512 个或 junction 超过 256 个时，相应 pass 跳过并计入 cap。随后 opt-in `consolidateFeatureGraph` 只连接不同 component 的 degree-1 endpoint，按 normalized distance + alignment penalty 确定性排序。两类 bridge 分别标为 `cleanupBridge` 和 `consolidationBridge`，不会伪装成 raw evidence。C03

已知风险：bridge 仍是局部一对一贪心。 双端方向、source 和 signed kind 已显著收紧误连，但没有全局 curve identity、primitive 或 surface-side 优化；密集近距离网络仍可能选错局部配对。运行时同时看 cleanup/consolidation 计数、branch-pair benchmark、component closure 与可视化。

1 recoverCircularCyclesThroughJunctions 因为分支、桥接、重复证据导致度数不为 2 的圆形边界。 先恢复高价值圆环，避免后续普通 trace 把它拆成几条开链。

5. 真正创建 FeatureLoop 的公共构造器

大部分 recovery 函数并不直接手写完整 loop，而是把顶点序列和统计信息交给 `FeatureLoopBuilder.cpp`。它提供三个核心能力：cycle 签名去重、从 stats 建立 `FeatureLoop`、把 loop 写回顶点。C05C06C07

cycleSignature：为什么能去重

`cycleSignature` 把 cycle 中每条边转成无向 edge key，然后排序拼接。这样同一个环无论从哪个顶点开始、顺时针还是逆时针，只要边集合相同，签名就相同。它被 junction chain 去重和 recovered cycle 去重共用。C05

addTracedLoop：普通 trace 的宽松入口

`addTracedLoop` 只要求顶点非空、`edgeCount > 0` 就会创建并 push 一个 `FeatureLoop`；如果它是闭合的，并且顶点数不少于 `minFeatureLoopVertices`，才会尝试 primitive fit。也就是说，当前实现中 `minFeatureLoopVertices` 对 traced loop 更像“primitive 拟合门槛”，不是“是否报告 loop 的硬门槛”。C06

这是读代码时最容易踩到的点。 `FeatureOptions` 注释写着“Minimum ordered vertices required before a traced curve is reported”，但 `addTracedLoop` 当前没有用它过滤所有 traced curve。短开链仍可能进入 `analysis.loops`，只是不会被 circle/ellipse/polygonal primitive 化。C11C06

addRecoveredCycle：恢复环的严格入口

与普通 trace 不同，`addRecoveredCycle` 很严格：点数必须达到 `minFeatureLoopVertices`，顶点不能重复，cycle signature 不能重复；然后统计边证据，做 primitive fit，并根据 recovery kind 决定是否接受。Circular kind 必须拟合成 circle/near-circle 且边中点也贴着圆；Polygonal kind 必须 fit 有效且分类为 `PolygonalLoop`。C07C15

6. 阶段一：通过 junction 双链恢复圆环

第一个 recovery 专门处理“圆环被 junction 打断”的情况。比如一个圆形边界上附着了分支，图中一些顶点度数不再是 2，普通闭环追踪会从 junction 出发，把圆周切成链。`traceJunctionChains` 会从每个 junction 沿着 2-valence 中间点向另一个 junction 走，得到 junction-to-junction chain。C08

这里叫 Circular，不是因为两条链拓扑上围成环就一定是圆，而是因为这个阶段只想抢救“像圆孔/圆柱边界”的高价值 CAD 环。最终是否接受由 `addRecoveredCycle` 的 circle/near-circle 拟合和 `cycleEdgesFollowCircle` 再确认。C07C15

7. 阶段二：small cycle basis 恢复多边形环

第二阶段处理的是小型、没有 weak-evidence edge 的多边形 cycle。这里“没有弱证据”同时要求 component 内不存在 normal-tensor 与 smooth-curvature edge，并不只是“非 tensor”。它不是枚举所有简单环，而是在每个连通分量上做 BFS 树；每条非树边和树路径组成一个 fundamental cycle，再交给 `addRecoveredCycle(Polygonal)` 验证。C09

为什么跳过弱证据分量

normal tensor 与 smooth curvature 边代表弱特征/软特征证据，可能来自局部法向变化或光滑曲率极值，而不是硬边界。这个阶段要从图论上“补闭合多边形环”，如果把弱 ridge 也拿来闭合，容易把噪声或浅 ridge 误当成分割边界。所以 `componentHasWeakEvidenceEdge`（覆盖 normalTensor 和 smoothCurvature 两种来源）为真时直接跳过。C09P05

Polygonal 的接受条件

`addRecoveredCycle(Polygonal)` 仍然会做 primitive fit，但它只接受分类结果为 `PolygonalLoop` 的 cycle。如果一个 cycle 几何上更像 circle/near-circle/ellipse，它不会在 small cycle basis 阶段以 polygonal 身份写入；圆形/椭圆可能由第一阶段、第四阶段或第五阶段处理。C07C13

8. 阶段三：追踪剩余开链和纯闭环

第三阶段是最像“沿边走”的部分。它维护一个 `visitedEdges`，先从所有 degree != 2 的种子点追踪开链，再对剩余未访问边追踪 degree=2 的纯闭环。C04 

flowchart TD
  A["visitedEdges = empty"] --> B["遍历 seed"]
  B --> C{"seed degree != 2?"}
  C -->|"是"| D["对每个未访问邻边 traceOpenChain"]
  C -->|"否"| E["先跳过"]
  D --> F["addTracedLoop"]
  F --> G["遍历 trace.graphEdges"]
  G --> H{"边未访问?"}
  H -->|"是"| I["traceClosedLoop"]
  H -->|"否"| J["结束"]
  I --> F
函数如何走停止条件是否可能 closed
traceOpenChain 从非 2-valence seed 出发，每一步选择不是 previous 且未访问的邻边。 遇到已访问边、回到 seed、当前点 degree != 2、或找不到 next。 如果回到 seed，会弹掉重复 seed 并置 `stats.closed = true`。
traceClosedLoop 从剩余未访问边出发，在 degree=2 的环中一直走。 遇到已访问边、回到 seed、或找不到 next。 正常纯环会在 current == seed 时置 closed。

trace 过程中会累计哪些统计

每走过一条边，`accumulateTraceEdgeStats` 会累计 edgeCount、boundary、dihedral、normalTensor、smoothCurvature、nonManifold、cleanupBridge，以及 convex/concave/unknown signed edge。这些统计进入 `FeatureLoop`，也帮助后续报告解释这个 loop 是由什么证据支撑的。C04C06

这一步不是“只要闭合才生成”。 open chain 也会调用 `addTracedLoop`。所以在当前实现中，`analysis.loops` 可以包含开链；它们的 `closed=false`、`primitive=Unknown`，但顶点仍会被标为 feature，给简化阶段提供保护信号。C04C06

9. 阶段四：primitive component fallback

第四阶段不再依赖“顺着边得到一个漂亮的顶点序列”，而是按 trace graph 连通分量收集顶点，然后问：这个分量整体是否像 circle、near-circle 或 ellipse？如果是，就把整个 component 当成一个闭合 primitive loop 写入。C12

跳过条件含义为什么这么做
已有 circular 顶点之前阶段已经恢复过圆环。避免重复创建相同圆环。

fit 不是 circle/near-circle/ellipse几何上不是当前 fallback 要保护的 primitive。多边形环已经由 small cycle 或 trace 负责。

10. 阶段五：circular vertex cluster fallback

最后一段是专门给“小型碎片化 CAD 圆孔”准备的。它从一个 trace component 里找“a - b - c 两条边都存在”的长度 2 路径作为三点圆种子，用圆的平面误差和径向误差收集 cluster，检查角覆盖范围，按圆周角排序后再验证“证据连通性”——cluster 相邻顶点对若没有特征边支撑，其角跨度累计不得超过整圈的 25%——最后做正式 primitive fit。C13

为什么这个阶段放最后

三点圆搜索比普通追踪更像“猜一个圆”。为了减少误判，它有几层保险：跳过含弱证据边（normal tensor 或 smooth curvature）的分量、跳过已有 circular loop 的分量、component 顶点数必须在合理范围内、种子路径扫描最多 32768 次、cluster 至少覆盖 270 度、cluster 必须由 trace 图特征边基本连通、最终还要 `fitPrimitive` 分类为 circular。C13

种子枚举本身也经过一次关键收紧：早期实现盲目枚举 component 内所有顶点三元组（O(n³)），既会把互不相连、只是恰好共圆的顶点（例如倒角棱柱不同竖直折痕上的同排角点）缝合成假圆，也会在只有 58 个顶点的网格上烧掉数秒。现在种子只来自 trace 图的长度 2 路径（复杂度 O(Σdeg²)），任何有证据的 ≥3 顶点圆弧必然包含这样的路径，所以不会漏掉真实圆；配合证据连通性门控，chamfer box 上的 detect 从 1735 ms 降到约 7 ms，恢复出的 loop 从 116 个降到 31 个，junction precision 从 0.29 恢复到 1.0（见 FeatureDetectionAnalytic.ChamferBoxJunctionPrecisionIsNotFloodedByCircularRecovery）。C13

保护阈值代码值意义
component 顶点上限120只处理小型 CAD 孔洞，避免大图搜索。
种子路径扫描上限32768确定性复杂度上限；达到上限说明穷举被截断，计入 circularRecoveryTruncated 诊断。
cluster 允许误差`max(3 * circleFitRelativeThreshold, 0.08) * radius`允许轻微碎片和不均匀采样。
角覆盖`>= 1.5 * pi`至少覆盖 270 度，避免一段弧误判成整圆。
证据连通性 gap 上限`kMaxCircularRecoveryGapFraction = 0.25`相邻候选对无特征边支撑的角跨度累计不超过四分之一圈；纯几何共圆不算证据，恢复只补小缺口、不发明圆。与 1.5π 角覆盖要求（最多缺四分之一圈）一致。

11. primitive 拟合如何决定 circle / ellipse / polygonal

primitive fit 在 `PrimitiveFit.cpp`。它先用 loop 顶点的协方差求局部平面（PCA 仍负责平面法向估计），再在平面内做圆与椭圆拟合：圆用 Taubin 代数拟合（Taubin 1991，一阶无偏，短弧/噪声/非均匀采样下不再系统性低估半径），Kåsa 最小二乘保留为确定性回退；椭圆用 Halíř-Flusser 直接最小二乘拟合（Fitzgibbon 约束 4ac−b²=1，3×3 缩减系统，保证输出真椭圆），major/minor 轴向来自 conic 转角而非旧的 PCA 二阶矩（后者仅作回退）；随后计算 radial、plane、ellipse 三类误差，根据相对 RMS/Max 误差和轴比分类。C15

junction 和 shared 的来源：保护 flag 与图级 junction 是两个语义

这里要区分两层。逐顶点保护 flag偏保守：真实分支点和被多个 recovered loop 共享的顶点都会被钉住。图级 junction 报告仍以 active valence > 2 为入口，`shared` 与 `endpoint` 单独报告；但每个 junction 现在还保存 incident branches 的 outward tangent/signed kind、最优 continuation pairs 和 ambiguous 标记。这样既保留 M007 的分支点定义，也能测“分支是否接对”，而不只测 junction 顶点集合。C16

为什么要写 tangent

tangent 是后续特征保护的重要方向信息。圆形 loop 用 `normal.cross(radial)` 得到切线；椭圆 loop 根据参数角计算切线；普通 loop 用邻接方向求 fallback tangent。这样 QEM/line feature 保护可以沿曲线方向约束，而不是只知道“这个点是 feature”。C05C14P07

15. 论文路线对照

从文献路线看，当前实现属于“CAD/STL 特征边检测 + 图追踪 + 闭合边界恢复”的工程化路径，而不是纯 curvature ridge/valley 或神经 wireframe。文献索引里的决策建议也明确：CAD/STL hard boundary 通常先检测二面角/边界/patch transition，再 trace continuous edges into loops，并用 loop closure 验证分割边界。P00P01

程序设计点对应文献路线当前实现选择论文位置
先检测硬边，再追踪成 loop CAD/STL feature line extraction 与 polygon crawling 都强调从局部边证据组织连续特征边。 `buildTraceGraph` + `traceRemainingFeatureLoops`，强依赖 mesh adjacency。 P01P02
闭合 loop 对分割和工程对象很重要 工程对象 mesh segmentation 通常需要闭合、一致的边界，缺口会导致区域泄漏。 cleanup 桥接 gap/junction，再用 cycle recovery 和 primitive fallback 尽量补闭合。 P03
normal tensor / smooth curvature 作为弱特征证据，但不强行补闭合 normal voting/tensor 方法适合 noisy crease 和 weak feature，确定性曲率 ridge/valley 方法适合光滑表面，但尺度和邻域都会影响结果。 tensor 与 smooth-curvature 边都可进 trace graph；small cycle/circular fallback 跳过弱证据 component，避免假闭环。 P04P05
图级 junction 和 curve network 是难点 wireframe/direction-field 文献强调 junction reasoning 和 graph connectivity 比单边打分更难。 当前实现用 deterministic graph tracing 和有限 fallback，尚未做方向场全局优化。 P06
loop 最终服务于简化保护 feature-preserving simplification 和 line quadrics 都需要可保护的曲线或方向约束。 `assignLoopToVertices` 写 tangent / primitive 参数，给后续 QEM 保护使用。 P07P08
当前实现的边界： 它没有做全局最优 cycle cover、方向场 wireframe、神经 junction 分类，也没有对所有 open chain 做曲线拟合；它是一套可解释、可诊断、偏 CAD/STL 的确定性 loop recovery 管线。
