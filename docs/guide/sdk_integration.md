# SDK Integration Guide

This project exposes two SDK surfaces:

- C++ API: ergonomic for applications built with a compatible C++ compiler,
  standard library, Eigen, and runtime settings.
- C ABI: recommended for binary SDK integration, Visual Studio property-sheet
  projects, C callers, plugin boundaries, and language bindings.

The C ABI is intentionally small and explicit. It never asks the caller to free
memory allocated by the DLL, and it never returns STL, Eigen, or C++ exception
types across the binary boundary.

## Installed SDK Layout

```text
bin/
  line_quadrics_qem.dll
include/
  line_quadrics_qem/api/*.h
  line_quadrics_qem/algorithms/simplification/*.h
  line_quadrics_qem/core/*.h
  line_quadrics_qem/features/*.h
lib/
  line_quadrics_qem.lib
share/
  line_quadrics_qem/thirdParty/eigen/include/Eigen/...
  line_quadrics_qem/msvc/line_quadrics_qem.props
  line_quadrics_qem/samples/basic_simplify.cpp
  line_quadrics_qem/samples/c_api_basic.c
```

On Linux and macOS, replace the Windows runtime/import library names with the
platform library names generated by CMake.

## Visual Studio Consumer

The primary industrial integration path is a normal Visual Studio project that
uses the installed headers plus either the import library for the DLL build or
the static library for the static build.

After installing the SDK, add this property sheet to the consuming `.vcxproj`:

```text
<install-prefix>\share\line_quadrics_qem\msvc\line_quadrics_qem.props
```

It adds:

- `include/` to the compiler include path,
- `lib/line_quadrics_qem.lib` to the linker input,
- a post-build copy of `bin/line_quadrics_qem.dll` next to the executable when
  the SDK was built as a DLL.

For a static SDK build, the same `.lib` name is used as the static library and
there is no runtime DLL to copy.

Pure C ABI users do not need Eigen headers. C++ API users should also set
`LQEigenIncludeDir` only when they want to override the Eigen headers shipped
with the SDK property sheet.

GoogleTest is not part of the runtime SDK. The repository keeps a prebuilt test
bundle under `thirdParty/googletest/prebuilt/` so local validation can run
without building GoogleTest source in the main project.

## SDK Layout Verification

The strongest local verification is to build the library, install it into a
local SDK directory, and then build an independent downstream project against
that installed directory only:

```powershell
cmake -S . -B build/sdk-release -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_COMPILER=gcc -DCMAKE_CXX_COMPILER=g++ -DLQ_ENABLE_INSTALL=ON -DLQ_GOOGLETEST_PROVIDER=prebuilt -DLQ_EIGEN_PROVIDER=vendored
cmake --build build/sdk-release --target sdk-consumer-test --parallel
```

This creates:

```text
build/sdk-release/sdk/
  bin/
  include/
  lib/
  share/line_quadrics_qem/
```

Then it configures `examples/sdk_consumer/` with
`LQ_SDK_ROOT=build/sdk-release/sdk`, builds one C++ API executable and one C ABI
executable, copies runtime DLLs from the installed SDK when needed, and runs
both through CTest.

## Optional CMake Consumer

The install can generate CMake config files for CMake-based consumers when
`LQ_INSTALL_CMAKE_CONFIG=ON`, but downstream Visual Studio projects do not need
them. Treat this as a secondary path beside the installed `.lib`, optional
`.dll`, headers, and `.props`.

```cmake
find_package(line_quadrics_qem CONFIG REQUIRED)
target_link_libraries(my_app PRIVATE line_quadrics_qem::line_quadrics_qem)
```

The helper copy function is a no-op on non-Windows platforms.

For C++ API use, keep the application and SDK on compatible MSVC toolsets and
runtime settings. For more stable plugin or third-party boundaries, prefer the
C ABI in `line_quadrics_qem/api/CApi.h`.

## C ABI Memory Rules

- Create one `LqContext` per integration thread or task when practical.
- Read error details with `lq_context_last_error(context)` after a non-OK
  `LqStatus`.
- Treat the returned error pointer as borrowed. It remains valid until the next
  SDK call using that context or until the context is destroyed.
- Create meshes with `lq_mesh_create(context)` and release them with
  `lq_mesh_destroy(mesh)`.
- Copy mesh data into the SDK with `lq_mesh_set_data`.
- Copy mesh data out with `lq_mesh_get_counts`, `lq_mesh_copy_vertices`, and
  `lq_mesh_copy_faces`.
- Caller-owned arrays stay caller-owned. SDK-owned handles are released only by
  SDK destroy functions.
- C++ exceptions are caught inside the C ABI and converted to status codes.

Minimal C flow:

```c
#include "line_quadrics_qem/api/CApi.h"

LqContext* ctx = lq_context_create();
LqMeshHandle* input = lq_mesh_create(ctx);
LqMeshHandle* output = lq_mesh_create(ctx);

lq_generate_mesh(ctx, "cylinder", 32, input);

LqSimplifyOptions options;
lq_simplify_options_init(&options);
options.target_ratio = 0.35;
options.preserve_feature_curves = 1;
options.feature_protection_mode = LQ_FEATURE_PROTECTION_PRIMITIVE_CURVES;

LqSimplifyReport report;
LqStatus status = lq_simplify_mesh(ctx, input, &options, output, &report);
if (status != LQ_STATUS_OK) {
  const char* detail = lq_context_last_error(ctx);
}

lq_mesh_destroy(output);
lq_mesh_destroy(input);
lq_context_destroy(ctx);
```

`LQ_FEATURE_PROTECTION_PRIMITIVE_CURVES` is the default SDK feature policy:
circle, near-circle, and ellipse loops are hard-protected; generic
polygonal/dihedral creases remain soft cost and legality-filter signals. Use
`LQ_FEATURE_PROTECTION_ALL_FEATURE_EDGES` only for the stricter legacy behavior.
