ManuMesh 当前算法与论文引用地图

本页所说算法以当前源码为准：src/simplification 负责 QEM/edge-collapse，src/feature_detection 负责特征证据、feature graph、cleanup、loop/primitive recovery，src/common/detail 提供局部边长、邻接和拓扑查询。论文引用使用 Mxxx 编号；完整索引在 docs/papers/README.md 与 docs/design/feature_detection_upgrade_2026_07_09.md。

读懂 ManuMesh 算法的推荐顺序

如果从零看当前实现，先读 docs/generated/notes/current-program-principles.html#deep-algorithm-walkthrough，再读 docs/generated/notes/current-program-principles.html#feature-recognition-deep-dive。前者按真实执行顺序解释网格如何变成拓扑、quadric、候选队列和 legality gates；后者专门解释特征识别如何从 edge evidence 变成 feature graph、loop、primitive、component confidence，并最终被 QEM 消费。

  1. 先看数据流：Mesh -> MeshEdgeInfoMap -> FeatureAnalysis -> quadrics -> candidate queue -> legality gates -> SimplifyReport。
  2. 再看特征识别：FeatureEvidence.cpp 产出边证据，NormalTensor.cpp 产出弱特征分数，FeatureGraphCleanup.cpp 把破碎证据整理成 component，FeatureLoopBuilder.cpp 和 PrimitiveFit.cpp 把图变成 loop/primitive。
  3. 最后看简化消费：FeatureConstraints.cpp 决定哪些 collapse 被拒绝，Quadrics.cpp 决定 feature curve soft quadric 如何加权，feature_components、graph_cleanup_*、feature_rejected、quality_rejected、error_rejected 解释算法为什么这样停。

4. 圆/椭圆 loop 的识别路径

这些结果不是只靠“孔边界有很多 feature edges”得到的。ManuMesh 会先用 boundary/dihedral/normal-tensor evidence 建 trace graph，再通过 cleanup 修复短 gap、删除 tensor-only spur、合并近 junction，随后才恢复 loop 并做 primitive fitting。

步骤代码位置结果表里怎么看失败时先查什么
边证据FeatureEvidence.cppfeature-report 里的 boundary/dihedral/tensor edge 数。featureAngleDeg、loopTraceAngleDeg、normal tensor threshold。
图清理FeatureGraphCleanup.cppgraphCleanupBridgedGaps、graphCleanupRemovedSpurs、graphCleanupMergedJunctions。若 bridge 很多，说明输入断裂或阈值太窄；若 spur 很多，说明 tensor 弱证据过宽。
loop 恢复FeatureTraceRecovery.cpp、FeatureCycleRecovery.cpp、FeatureCircularRecovery.cppfeature loop 数、closure rate、endpoint 数。loop 数少时先看 untraced feature edges 和 component 断裂。
primitive fittingPrimitiveFit.cppcircle / near-circle / ellipse 数、radial/plane residual。残差高说明不能硬当圆孔保护，应降级为 polygonal/generic feature。
简化消费FeatureConstraints.cpp、Quadrics.cppprimitive rejection、projected placement、feature drift。rejection 高但目标达不到时，优先调保护模式、curve budget、target ratio。

对应文献路线是：M016/M018/M019 支持 CAD/STL feature graph tracing，M024/M025 强调 segmentation 需要闭合边界，M026 提醒弱特征要 consolidated 后再保护，M028/M029 支持 feature-preserving simplification 中对特征顶点/边使用更强约束。

特征保护路线图

第一阶段已经实现。--preserve-feature-curves 默认使用 --feature-protection-mode primitive-curves：圆、近圆和椭圆 loop 保持硬保护，generic polygonal 与 dihedral crease 作为软成本/guard 输入，而不是自动硬锁。

严格保护模式可通过 --feature-protection-mode all-feature-edges 启用。SDK 也暴露 FeatureProtectionMode / ManuMeshFeatureProtectionMode，包含 none、circular-only、primitive-curves 和 all-feature-edges。

  • Mars wheel：all-feature-edges 停在 10974 面，feature rejection 为 468702；primitive-curves 达到 9066 面，feature rejection 为 31，generic rejection 为 0。
  • Differential gear：all-feature-edges 停在 2662 面，feature rejection 为 68993；primitive-curves 达到 1236 面，feature rejection 为 0。
  • Fandisk：两种模式都达到目标，但 generic feature rejection 从 513 降到 0。

设计说明：docs/design/feature_protection_roadmap.md。
