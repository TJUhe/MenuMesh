1. 学习方法与完成标准

读 fixture 和 options -> 手算目标面数、边界/特征约束与预期拒绝原因 -> 只运行一个 gtest -> 从 QEMSimplifier 进入 SimplificationRun -> 跟踪 Candidate -> placements -> legality -> topology update -> 对照 SimplifyReport 与最终几何断言 -> 必要时输出 debugUtil HTML

每个案例至少回答：候选边来自哪里；placement 为什么排在第一；失败属于拓扑、法向、质量、误差、相交、特征还是纹理；折叠后哪些 face/vertex/candidate 被更新；测试断言验证的是局部机制还是最终质量。

完成标准：给出一条候选边及 options 后，你能在运行前说出主要 placement、可能拒绝原因和报告计数变化，并能在源码中定位该判断。

观察options_、target face count、输入/输出面数、lastReport()。先确认 API/Pimpl/feature analysis 的所有权，再进入算法细节。

观察合并 quadric、矩阵秩、unconstrained optimum、along-edge optimum、端点/中点候选和各自 cost。不要把“最低代价”误认为“必定合法”。

单元 3：拓扑合法性与完整 link condition

观察keep/remove link 的顶点与边集合、edge link、boundary component、重复面检测。先理解集合等式，再看特殊分支。

单元 4：几何合法性 gate

断点evaluateCollapseAttempt、collapsePlacementRejectReason、checkLocalError、checkLocalIntersections。

观察CollapseRejectReason、new one-ring triangles、normal dot、triangle quality、reference distance 和 spatial candidates。记录 gate 顺序，因为一次 placement 只会上报首先命中的原因。

观察curve id/kind/confidence、hard/soft 状态、line quadric weight、feature drift、primitive residual。结合特征识别教程理解 analysis 如何被下游消费。

单元 7：纹理 chart 保护

观察端点 chart cluster、remove-to-keep mapping、旧/新 UV 面积、scalar UV cost 和更新后的逐面角 UV。几何 placement 仍在三维空间中。

单元 8：拓扑不变的质量 refinement

观察切向位移、feature tangent、旧/新局部最差质量、error envelope 和相交检查。确认 refinement 不改变 face connectivity。

单元 9：解析真值、外部模型和性能

学习目标把局部机制放回最终质量门：face budget、边界/闭合拓扑、sampled distance、feature drift、最差三角形、拒绝计数、确定性和耗时。

5. 用 debugUtil 定位折叠位置

DebugUtil 插桩调用当前暂时注释；定位候选、被拒 placement 或简化前后差异时直接使用结构化 metrics 和测试断点：

MANUMESH_DEBUG_UTIL_EDGE_LABEL(
    "collapse_candidate", inputMesh, keep, remove,
    manumesh::debugUtil::UseCase::Candidate,
    "candidate before legality checks");

MANUMESH_DEBUG_UTIL_BEFORE_AFTER(
    "simplification_result", inputMesh, outputMesh);

输出目录和环境变量详见 debug_util_usage.md。HTML 只回答“发生在哪里”，最终结论必须回到 gtest 的数值、拓扑和报告断言；临时插桩诊断完成后删除。

6. 常见误区

现象正确排查方向
队首 cost 最低却没折叠检查 stale version、link condition 和 placement legality；cost 只负责排序。
保护边界后面数降不下去检查目标是否要求破坏最小拓扑，以及边界/特征 hard constraint 是否冻结了候选。
某个拒绝计数为 0gate 有固定顺序，候选可能先被更早的原因拒绝。
单元测试通过但模型变形补看 analytic/external/performance 层的距离、feature drift 和质量门。
debugUtil 没输出确认使用独立 debugUtil preset、Debug 配置，并重新编译相关对象。
