QEM 二次型展开速查：当前到底加了哪些项

ManuMesh 当前把所有软几何成本统一累积到齐次二次型。设 x 是候选新顶点位置，x_h=[x,1]^T，每个顶点保存 Q=[[A,b],[b^T,c]]，则候选代价为 E(x)=x_h^T Q x_h=x^T A x+2 b^T x+c。折叠边 (i,j) 时先做 Q_edge=Q_i+Q_j，再解 A x=-b；若谱条件（minEval/maxEval > 1e-12）拒绝全空间最优，先尝试沿折叠边的一维最优 t* = (rhs·d − dᵀA a)/(dᵀA d)（rank-2 quadric——直棱、边界折痕——的良定情形，分母用尺度不变相对阈值判定），仍失败才落回端点/中点候选；边界边坍缩的 placement 另按 Lindstrom-Turk 边界守恒约束投影（src/simplification/Placement.cpp）。

二次型项展开到 A,b,c参数与默认值作用与引用
面平面 QEMpi=[n,-n.p]，Q += area/3 * pi*pi^T。等价于 E=a(n.x-n.p)^2，所以 A+=a nn^T、b+=-a(n.p)n、c+=a(n.p)^2。无独立开关；退化面使用 1e-6 * representativeArea * pointQuadric，保持与正常 QEM 相同的 L^4 缩放量纲。主几何误差，来自 M002 Garland-Heckbert 1997。
普通 Line QuadriclineQuadric(p,n) 取两个与局部法线 n 垂直的单位方向 u,v，加入 Q_l=pi_u*pi_u^T+pi_v*pi_v^T。展开为 E_l=||(I-nn^T)(x-p)||^2，即惩罚切向漂移。useLineQuadrics=true，lineWeight=1e-3。默认分支：Q_i += w_i area_i Q_l。补平坦区 QEM 切向不满秩问题，来自 M004 Liu-Rahimzadeh-Zordan 2025。
特征加权 Line Quadric非 uniform 模式下 w_i=lineWeight+featureBoost*s_i；s_i 来自 dihedral、normal-tensor persistence、height 或 xband。normal-tensor 模式只给满足 normalTensorMinPersistentScales 的顶点写入 persistent score。weightMode=uniform，featureBoost=0.05；常用调试值 dihedral/normal-tensor + 0.08。featureAngleDeg=40，normalTensorFeatureThreshold=0.16，normalTensorScaleCount=1。让硬边、弱 ridge 或指定区域获得更高排序成本；feature evidence 参考 M007/M012/M013/M015/M016，弱特征参考 M026。
Adaptive Scale 分支（Wang 2008 解耦）若 adaptiveScale=true，quadric 只加干净的 adaptiveBaseLineWeight*area_i*Q_l 基础项；featureBoost 不再放大 quadric（旧行为会扭曲 placement），改为逐顶点 priorityScale = 1 + max(0,featureBoost)*s_i，只乘候选队列的排序代价（取折叠边两端点最大值，折叠时按 max 传播到 keep 端）。adaptiveScale=false，adaptiveBaseLineWeight=1e-2。非 adaptiveScale 路径 featureBoost 仍按旧行为加进 line weight。Wang 2008 优先级/placement 解耦：排序看特征，placement 求解不受特征权重污染；实现见 Quadrics.cpp 与 CandidateQueue.cpp。
边界 Plane Quadric边界边 (a,b) 只有一个邻接面时，取 m=normalize(n_face x e_hat)，加入 Q_b=boundaryWeight*|e|^2*pi_m*pi_m^T 到两个端点。它的 A=boundaryWeight*|e|^2*mm^T，秩 1；边长平方使该项与面积加权 face QEM 同为 L^4 缩放量纲。boundaryWeight=0.0 默认关闭；常用 1-10。硬边界保护另看 preserveBoundary。减少开放边界沿面内法向漂移；扩展 QEM 思路参考 M003，工程 guards 参考 M030-M033。
特征曲线 Tangent-Line Quadric当检测到 loop/primitive 后，对特征顶点用切线 t 调用 lineQuadric(p,t)，即 E_curve=eta*rho*area*||(I-tt^T)(x-p)||^2。这里 rho=0.35+0.65*confidence。preserveFeatureCurves=false 默认关闭；featureCurveWeight=0.05，常用 0.08；featureComponentMinConfidence=0.35 只影响 high-confidence component 报告计数，不过滤 component 或保护。允许沿特征线滑动，惩罚离开曲线；组合 M004 line quadrics、M016 CAD feature line、M026 weak-feature consolidation、M028/M029 feature-preserving simplification。
Primitive 投影与硬过滤圆/椭圆/多边形不是当前 Quadrics.cpp 里的单独径向二次型；当前代码用 tangent-line quadric 排序，再由 projectToCircle/projectToEllipse/projectToPolygonal、maxFeatureCurveDeviationRatio 和 featureProtectionMode 控制最终位置与是否拒绝折叠。maxFeatureCurveDeviationRatio=0 表示关闭曲线漂移预算；featureProtectionMode=PrimitiveCurves。圆/椭圆阈值默认均为 0.05。把“软成本排序”和“硬合法性保护”分开，符合 M030-M033 edge-collapse 工程建议。
纹理失真标量项（不进 quadric 矩阵）启用 preserveTexture 且网格带逐角 UV 时，排序代价变为 E_total(p)=E_geometry_4x4(p)+textureWeight*E_uv_local(p)，其中 E_uv_local=edgeLength^2*Σ(faceArea*cornerUvDisplacement^2)/meanLocalUvEdgeLength^2。它是排序期按候选 placement 现算的标量附加项，不展开进 A,b,c，不改变 Mat4 维度与 placement 求解；chart 配对/UV 定向/有符号面积检查作为硬过滤另行拒绝坍缩。preserveTexture=false 默认关闭（关闭时与旧无纹理路径 bit-exact）；textureWeight=1.0，textureSeamTolerance=1e-8，minTextureAreaRatio=1e-8。诊断：textureProtectedEdges、textureRejectedCollapses。仅 C++ API，CLI 未暴露。不走 M003 属性扩维（n×n quadric）路线；按 M033 工程拆分做局部标量排序项 + 显式合法性策略，与 M004/085 的 4×4 line-quadric 主干兼容。实现 src/simplification/TextureProtection.cpp，设计 documentation/design/texture_aware_qem.md。
带合理参数的数值展开例子

为了看清量级，假设坐标单位是 mm，某顶点 p=(10,5,0)，barycentric 顶点面积 a_i=2.0，候选新位置写作 x=(x,y,z)。实际折叠候选会把两端点 Q_i+Q_j 相加；下面先看单个顶点的一项怎样进入 A,b,c。

例子代入参数展开后的二次型读法
面平面 QEM平面 z=0，n=(0,0,1)，a=2.0E_plane=2*z^2，A=diag(0,0,2)，b=(0,0,0)，c=0离开面法向 0.2 mm 的代价是 2*0.2^2=0.08。
普通 Line QuadriclineWeight=1e-3，n=(0,0,1)，a_i=2.0，所以 alpha=0.002E_line=0.002*((x-10)^2+(y-5)^2)，A=diag(0.002,0.002,0)，b=(-0.02,-0.01,0)，c=0.25切向漂移 1 mm 只加 0.002，它是稳定排序的小正则项，不应压过平面 QEM。
特征加权 Line QuadricweightMode=normal-tensor，persistent score s_i=0.6，lineWeight=0.001，featureBoost=0.08，得 w_i=0.001+0.08*0.6=0.049，alpha=0.098E_feature_line=0.098*((x-10)^2+(y-5)^2)，A=diag(0.098,0.098,0)，b=(-0.98,-0.49,0)，c=12.25同样 1 mm 切向漂移，代价从 0.002 升到 0.098，约 49 倍；这就是弱特征被 QEM 排序“看见”的方式。

特征曲线 Tangent-Line Quadric切线 t=(0,1,0)，featureCurveWeight=0.08，component confidence 0.8，rho=0.35+0.65*0.8=0.87，alpha=0.08*0.87*2=0.1392E_curve=0.1392*((x-10)^2+z^2)，A=diag(0.1392,0,0.1392)，b=(-1.392,0,0)，c=13.92沿 y 方向滑动不罚，离开特征线横向/法向才罚；这是“允许沿孔边走，但不要偏离孔边”。

例如同一个候选位移 x=(11,5,0.2)：平面项给 0.08，普通 line 项只给 0.002，normal-tensor 特征加权 line 项给 0.098。所以默认 line quadric 是温和正则；一旦 feature score 和 featureBoost 介入，它才会变成明显影响 collapse 排序的特征保护成本。

为什么识别到边界、dihedral 或 normal-tensor 特征后要提高 Line Quadric 权重

先把一个容易误解的点说清楚：提高 lineWeight 或 featureBoost，确实会改变 A x=-b 的最小误差位置。它会让位置从“纯 plane QEM 的最优点”偏向“更靠近原顶点法线支撑线、切向漂移更小”的点。因此这不是免费的精度提升，而是一个有意加入的软正则项。M004 line quadrics 的核心价值，正是给标准 QEM 在平坦或近似平坦区域缺失的切向方向补一个小惩罚；M030-M033 的 edge-collapse 工程路线也强调，QEM/line quadrics 负责候选排序，真正危险的 collapse 仍要交给拓扑、边界、特征和质量过滤器。

当前代码里，weightMode=dihedral 会把开边界边记为 score=1，把超过 featureAngleDeg 的二面角边按强度写入端点分数；weightMode=normal-tensor 则使用满足 normalTensorMinPersistentScales 的 persistent feature score。随后普通 line quadric 的权重变成 w_i=lineWeight+featureBoost*s_i。这意味着边界、硬折痕、弱 ridge 附近的候选点，如果试图沿局部切平面大幅滑走，会在优先队列里付出更高代价。

疑问准确回答对应代码/参数
为什么识别到特征还要加 line 权重？因为 plane QEM 主要惩罚离开局部平面，很多特征破坏发生在切向：点沿表面滑过折痕、孔边被拖圆、边界轮廓缩进。Line quadric 惩罚 ||(I-nn^T)(x-p)||^2，正好给这种切向漂移加成本。Quadrics.cpp::lineQuadric，lineWeight，featureBoost
这会不会让最小误差位置更偏？会。它会偏离纯 plane QEM 的最优点，但这个偏移的方向是“少做切向漂移”。如果纯 plane QEM 本来在切向不满秩或近似不满秩，那么这个偏移反而让候选 placement 更稳定。solvePlacementCandidates() 用合并后的 Q_i+Q_j 求解
为什么特征附近要比普通平面更强？普通平面内的小滑动通常视觉影响不大；特征线附近同样大小的滑动可能跨过 CAD patch boundary、浅 ridge 或孔边。提高 w_i 让这些 collapse 排序靠后，给非特征区域优先被简化的机会。w_i=lineWeight+featureBoost*s_i
边界线也靠 line 权重保护吗？不是只靠它。开边界在 dihedral weight mode 下会得到高 feature score，从而减少切向漂移；但真正的边界形状和拓扑还要看 boundaryWeight 的边界 plane quadric、preserveBoundary 的硬策略和 topology guards。addBoundaryQuadrics()，preserveBoundary
normal tensor 弱特征会不会误检后过度保护？会有这个风险。normal-tensor 路径用 persistent score、最少支持尺度和 edge alignment 降低单尺度噪声；component confidence 在 Quadrics.cpp:195 通过 0.35 + 0.65·confidence 连续缩放软 quadric。注意 featureComponentMinConfidence 只是报告阈值，不会过滤弱特征或关闭保护。normalTensorFeatureThreshold，normalTensorMinPersistentScales，VertexFeature::confidence

可以用一个二维化的例子看直觉。假设局部平面是 z=0，纯 plane QEM 是 E_plane=2*z^2。候选点从 (10,5,0) 滑到 (11,5,0) 时，纯 plane QEM 代价仍是 0，因为它没有离开平面。加入普通 line quadric 后，代价多出 0.002；如果 normal-tensor persistent score 是 0.6 且 featureBoost=0.08，同样 1 mm 切向滑动代价变成 0.098。这并不是说几何误差突然大了 49 倍，而是系统在告诉优先队列：“这里像特征支撑，不要把切向漂移很大的 collapse 排得太靠前。”

因此正确的调参原则不是“特征越强，line 权重越大越好”。更稳的顺序是：保持基础 lineWeight 小，让它只修补平坦区病态；让 featureBoost 只放大高置信的 dihedral/normal-tensor 证据；把圆、椭圆、polygonal loop 交给 featureCurveWeight、primitive projection 和 hard feature policy；最后用 feature_rejected、generic_feature_rejected、max_orig_to_simp 和 feature drift 去判断是否过度保护。这个取舍也对应 M026 弱特征整合和 M030-M033 collapse guards 的思路：先让特征证据形成可靠 support，再决定软成本、硬保护或后处理投影。

因此当前总能量可读成：E = E_plane + E_line(weightMode) + E_boundary + E_feature_curve，启用 preserveTexture 时再加排序期标量项 textureWeight*E_uv_local；拓扑、边界、特征保护、法向翻转、三角形质量、局部误差、自交检查以及纹理 chart/有符号 UV 面积检查不是二次型项，而是候选折叠通过 QEM 排序之后的硬过滤。

1. ManuMesh 当前实现的定位

ManuMesh 当前实现不是一个通用几何处理框架，也不是单文件 QEM demo。它的目标是把经典 QEM、2025 line quadrics 思路、CAD/STL 特征识别、坍缩合法性检查、SDK/C ABI 和命令行验证收拢到一个可构建、可测试、可集成的 C++17 动态库里。

这意味着它的评判标准和开源库略有不同：我们不是追求覆盖所有网格算法，而是优先把“工业件三角网格能否在简化后保持孔、硬边、圆/椭圆 loop、边界和拓扑合法性”这件事做成可审计流程。

一句话概括

CGAL/OpenMesh 更像成熟的可组合框架，libigl 更像清晰的研究与教学工具，MeshLab/VCGLib 更像实用滤波器集合；ManuMesh 当前实现更像一个正在成形的专用工业 mesh kernel，重点是 QEM + line quadrics + 特征约束 + SDK 交付。

CGAL Surface Mesh Simplification 策略化 surface mesh simplification，围绕 edge collapse 组织 cost、placement、stop predicate、filter 和 constrained edges。 把“代价排序”和“能不能坍缩”拆开；用策略对象表达 placement/filter；把受约束边作为一等输入。 模板和概念体系较重；通用 SMS 不直接表达 line quadrics、圆/椭圆特征投影、当前 C ABI 报告字段和ManuMesh CLI 指标。 SimplificationRun 中把 quadric cost、feature policy、boundary policy、legality guard、report counters 分层；但保持一个轻量 SDK API。
OpenMesh Decimation Framework 基于半边网格的 decimater，支持连续 cost module 和二值 legality module 组合。 一个队列优先级模块不应该吞掉所有逻辑；normal、aspect ratio、Hausdorff、topology 等检查应作为独立 veto。 需要引入 OpenMesh 数据结构和模块体系；默认不提供ManuMesh 需要的 CAD primitive loop 保护、line-quadric 权重和 SDK 安装边界。 ManuMesh 当前暂用简单 Mesh exchange format + 可复用的 mesh_edit::DynamicTopology（已从简化器私有实现迁入 src/mesh_edit 基础模块），避免公共 API 直接绑定半边框架。
libigl qslim / decimate 紧凑的 QEM/qslim 与 decimation 工具，适合作为算法阅读和 baseline。 QEM 的核心可以保持小而清晰：累加平面 quadric，维护候选边队列，按目标面数停止。 更偏研究/工具箱调用；工业 STL 的边界、特征 loop、局部误差、报告计数和 C ABI 不是它的主要交付面。 保留标准 QEM baseline，并在其上叠加 line quadrics、feature curve quadrics 和合法性过滤，便于对比普通 QEM 与增强版本。
MeshLab / VCGLib / PyMeshLab quadric decimation 实用型三角网格滤波器，参数覆盖 boundary、normal、topology、quality、planar quadric、weighted simplification 等常见工程开关。 用户需要可解释旋钮和可复现输出，而不是只给一个 ratio；质量、边界、法向和拓扑保护必须能单独开关。 滤波器接口更适合批处理和 UI；很难把每次拒绝坍缩的原因、特征 loop 所属关系和 SDK ABI 诊断直接嵌入下游应用。 CLI 输出 STL/CSV，SimplifyReport 区分 feature、boundary、topology、normal flip、quality、intersection、local error 等拒绝原因。
Fast Quadric Mesh Simplification 等轻量 QEM 实现 代码短、速度快、容易嵌入，用于快速减面或游戏/可视化资产处理。 性能和依赖控制很重要；QEM 内核不应为了架构漂亮而牺牲可部署性。 通常缺少完整特征图、工业合法性检查、误差 envelope、详细报告和 SDK 集成策略。 ManuMesh 当前保持 Eigen + 自有小型拓扑缓存，优先把严格检查做成局部/增量查询，避免每次坍缩全局扫描。

3. 我们学习到了什么

3.1 QEM 是排序骨架，不是全部规则

成熟库都没有把最小 quadric cost 当作唯一真理。CGAL/OpenMesh 的共同启发是：cost 负责“先试谁”，filter/module 负责“能不能做”。ManuMesh 因此把 solvePlacementCandidates() 的候选位置送入 feature、boundary、topology、normal、quality、intersection 和 local-error 检查。placement 侧同样借鉴了成熟库：全空间最优被谱条件拒绝后先解沿折叠边的一维最优（GH97 三级回退链，rank-2 quadric 的良定情形），边界边坍缩采用 Lindstrom-Turk 边界守恒约束投影（与 CGAL SMS 默认 LindstromTurk placement 同源的思路，实现在 src/simplification/Placement.cpp）。

3.2 合法性要比目标面数更硬

如果为了达到 ratio 牺牲 link condition、边界、法向翻转或自交，结果在工业件上不可用。ManuMesh 宁愿报告 rejection-limit 或 no-candidates，也不在 guard 失败时强行坍缩。

3.3 用户需要可解释的参数和计数

MeshLab 类工具的实用价值之一，是把边界、法向、质量、planar quadric 等开关暴露给用户。ManuMesh 对应地提供 lineWeight、featureProtectionMode、maxLocalErrorRatio、minTriangleQuality 等参数，并在 report 中解释拒绝原因。

3.4 数据结构要服务于验证闭环

OpenMesh 的半边结构很完整，但ManuMesh 当前公共 API 先保留简单 Mesh，把可变拓扑、空间索引和候选队列放在私有实现里。这样下游 SDK 调用稳定，同时内部还能逐步替换成更强的 editable topology。

借鉴点 当前代码里的落点 为什么重要
cost / placement / legality 分离 Quadrics.cpp、FeatureConstraints.cpp、CollapseLegality.cpp 同一个 QEM 候选位置可能因特征、边界、局部误差或三角形质量被拒绝，不能混成一个黑箱代价。
模块化拒绝原因 SimplifyReport 中的 featureRejectedCollapses、topologyRejectedCollapses 等字段 验证时能判断是参数过严、特征检测过密，还是拓扑/质量 guard 真正拦住了危险坍缩。
保留普通 QEM baseline useLineQuadrics=false 或 CLI 的 standard QEM 路线 没有 baseline 就无法证明 line quadrics 和 feature policy 真的改善了目标模型。
局部增量检查 DynamicTopology、SpatialFaceIndex、候选队列版本号 严格检查必须跑得动。大模型上每步全局扫描会把验证流程拖垮。
把受保护结构显式建模 FeatureGraph、FeatureLoop、圆/椭圆 primitive 参数 CAD/STL 的孔、法兰边和硬折线不是单点属性，必须作为 loop 或 curve 结构被跟踪。

4. ManuMesh 当前实现还有哪些不足

维度 成熟开源库的优势 ManuMesh 当前实现的不足 风险
通用性 CGAL/OpenMesh 覆盖更多 mesh 类型、属性、拓扑操作和生态工具。 ManuMesh 当前只聚焦简化、特征检测、指标和 SDK 集成，还不是完整 polygon mesh kernel。 遇到修复、重网格、布尔、属性传播时仍需外部工具或后续模块。
鲁棒几何 CGAL 在几何谓词、内核和鲁棒性方面积累深。 本轮几何谓词已做成尺度不变的相对阈值策略：kRelativeIntersectionEps=1e-9，Möller-Trumbore 行列式与其尺度上界比较（无量纲 eps），2D 谓词区分 epsLen=eps·scale 与 epsArea=eps·scale²，网格均匀缩放不改变自交判定。但仍是 double 浮点近似，不是 CGAL 式精确算术/可证谓词。 极端尺度、近退化三角形、几乎共面的工业 STL 仍可能出现误判。
拓扑结构 OpenMesh 半边结构天然适合局部编辑、属性绑定和邻接遍历。 本轮 DynamicTopology 已迁入可复用的 src/mesh_edit 基础模块，但与公共 MeshTopology 仍未统一成同一套结构。 后续 repair/remesh/boolean 共享拓扑能力时需要一次结构升级。
特征图 成熟库虽然不一定专注 CAD primitive，但框架通常能承载更复杂属性和约束。 当前 feature graph 已能恢复一部分 junction/cycle，但多环共享、嵌套 loop、长样条特征和冲突归属仍不完整。 密集工业模型可能过度保护、漏保护，或把一条真实特征切成多个碎片。
验证数据 MeshLab/CGAL/OpenMesh 有更长时间的用户验证和生态反馈。 当前测试正在增长，但还缺少系统的 labeled feature precision/recall、严格 Hausdorff envelope 和跨平台性能基线。 算法看起来通过了若干样例，但还不能宣称覆盖任意 CAD/STL 输入。
不要误读 ManuMesh 当前实现

ManuMesh 当前已经超过“普通 QEM demo”，但仍不是 CGAL/OpenMesh 级别的通用几何平台。它更像一个专用能力逐步做深的工业内核：在 ManuMesh 关心的 QEM、line quadrics、特征保护和 SDK 验证上更聚焦，在通用网格生态和鲁棒内核上仍要继续补课。

5. 为什么 ManuMesh 当前实现要这样做

5.1 为什么要加入 line quadrics

标准 QEM 对局部平面区域的法向误差敏感，但对切向漂移约束弱。line quadrics 给每个顶点的法向线加入点到线距离项，相当于给平面切向也补上可控惩罚。这样做不是为了替代 QEM，而是为了让普通 QEM 在平坦区域的病态求解和采样漂移更可控。

5.2 为什么要做 feature graph 和 primitive 保护

CAD/STL 输入没有 B-Rep 语义，孔、凸台、法兰边、椭圆环和硬边只能从三角网格推断。只把 feature 作为顶点 bool 会丢掉“这是一条闭合 loop”以及“这条 loop 拟合成圆/椭圆”的信息。ManuMesh 因此把 FeatureLoop、FeaturePrimitiveType 和顶点的 loop ownership 写入检测结果，再在简化时投影和限制坍缩。

ManuMesh 额外保留的信息 为什么开源 decimator 的普通约束不够 对应实现
edge evidence kind 同样是 feature edge，boundary、dihedral、normal-tensor weak edge、cleanup bridge 的可信度不同，不能统一硬锁。 FeatureGraphEdge
loop / primitive ownership 圆孔和椭圆孔需要按整条 loop 控制 drift；单个顶点 bool 无法表达“同一条圆”。 FeatureLoop、PrimitiveFit.cpp
component confidence 弱 ridge 需要 consolidated support 后再决定软成本或硬保护，否则很容易把噪声当 CAD 语义。 FeatureComponent、FeatureGraphCleanup.cpp
diagnostics and benchmark hooks 商业 SDK 需要解释“为什么没达到目标面数”或“为什么孔漂移”；只给最终 mesh 不够。 SimplifyReport、feature-benchmark

这也是 ManuMesh 与通用 decimation library 的分工：CGAL/OpenMesh/PyMeshLab 提供很好的 edge-collapse 框架参考，但 ManuMesh 需要把 M007/M016/M018/M019 的 CAD/STL feature tracing、M009/M012/M013/M015 的 normal tensor 弱特征证据、M024/M025 的闭合边界要求和 M026 的弱特征 consolidation 统一成一个可消费的 FeatureAnalysis。

5.3 为什么默认不是保护所有特征边

早期 --preserve-feature-curves 太容易把碎片化工业特征全部硬锁住，导致模型达不到目标面数。现在默认 primitive-curves：圆、近圆、椭圆等工程语义更强的 primitive 作为硬保护；普通多边形/二面角特征更多作为软代价和 guard 输入。这样是在“保住关键几何”和“允许简化继续发生”之间取中间值。

5.4 为什么要自己保留 SDK 边界

直接把 CGAL/OpenMesh 的数据结构暴露给下游，会让 ABI、编译器、模板依赖和部署复杂度进入客户工程。ManuMesh 当前对外保留 Mesh、SimplifyOptions、SimplifyReport 和 C ABI，内部再逐步增强拓扑与几何检查。这让工程集成比算法框架更窄，也更容易在 Visual Studio/C API 场景下落地。

6. 后续改进方向

  1. 把 legality policy 明确模块化，继续向 CGAL/OpenMesh 的 cost、placement、filter、stop 分离靠拢。
  2. 继续把 DynamicTopology 与公共 MeshTopology 演进成统一的 editable topology——第一步已完成：DynamicTopology 已迁入可复用的 src/mesh_edit 基础模块，供 repair/remesh/boolean 后续共享。
  3. 引入更严格的 Hausdorff 或 envelope 误差过滤，替代当前局部采样误差的保守近似。
  4. 增强 feature graph ownership：处理多环共享、junction、嵌套 loop、样条/多段线特征和 per-loop 预算。
  5. 继续校准弱证据通道：normal tensor 的多尺度 smoothing/persistence 与本轮新增的确定性 smooth-curvature 检测器（SmoothCurvature.cpp，opt-in、默认关闭）均已落地，后续重点是降低非均匀采样和噪声导致的误检。
  6. 建立 labeled CAD/STL 验证集，报告 feature precision/recall、loop recall、normal error、topology delta、triangle quality 和运行时间。

6A. 属性/纹理支持：ManuMesh 当前做法的定位

开源 decimator 处理纹理/属性大多沿 Garland-Heckbert 1998（M003）的“属性扩维”路线：把 UV/颜色等属性拼进位置向量，quadric 从 4×4 扩成更高维的 n×n，让一次线性求解同时给出最优位置和最优属性。MeshLab/VCGLib 的 “Quadric Edge Collapse Decimation (with texture)” 滤波器和 meshoptimizer 的属性感知简化（simplifyWithAttributes）都属于这一族思路（具体实现细节各有取舍）；OpenMesh decimater 与 CGAL SMS 则通常靠约束边（constrained edges）或外部预处理来保住纹理接缝，不把纹理当一等公民。

ManuMesh 本轮落地的纹理感知简化（设计文档 documentation/design/texture_aware_qem.md，实现 src/simplification/TextureProtection.cpp）刻意选了另一条路：不扩维。几何 quadric 保持 4×4 齐次 Mat4，placement 候选（端点/中点/稳定 3D QEM 最优点）与求解完全不变；纹理以两种显式机制介入——排序期的局部标量代价 E_total(p)=E_geometry_4x4(p)+textureWeight*E_uv_local(p)，以及坍缩合法性检查（局部 UV chart 一一配对、存活 UV 三角形有符号定向与 minTextureAreaRatio 面积下限）。UV 采用角拥有（corner-owned，Mesh::faceTexCoords）：一个几何顶点可以在接缝两侧属于不同 chart，seam 语义因此不需要复制顶点即可表达。

维度 属性扩维路线（M003 族） ManuMesh 当前做法
quadric 维度 (3+m+1)×(3+m+1)，位置和属性联合求解 保持 4×4，属性不进矩阵、不进解
属性对结果的影响 直接影响最优位置与最优属性本身 只影响候选排序（标量加权）与是否允许坍缩（硬过滤）；坍缩接受后按边参数插值更新受影响面角 UV
seam 表达 顶点级属性通常需要 wedge 或顶点复制来表达接缝 corner-owned UV 原生表达 seam；双侧 seam 两侧 chart 一致配对时允许坍缩，跨 seam 合并 chart 归属的坍缩被过滤
数值与兼容性 求解维度、条件数分析随属性数变化 line-quadric 满秩分析、回退策略原样成立；preserveTexture=false（默认）时几何输出与旧无纹理路径 bit-exact
复杂度 属性空间矩阵分解随维度增长 期望 O(k) 局部 chart 哈希与三角检查（k 为一环规模），无全局参数化/图集遍历，edge-collapse 渐近复杂度不变
暴露面 各库以滤波器参数或 API 权重暴露 C++ SimplificationOptions：preserveTexture=false、textureWeight=1.0、textureSeamTolerance=1e-8、minTextureAreaRatio=1e-8；诊断 textureProtectedEdges、textureRejectedCollapses。CLI simplify 未暴露纹理开关

取舍也要说清楚：扩维路线让属性直接参与最优点选择，理论上能在“位置换属性”的连续权衡里找更优解；ManuMesh 的拆分则换来求解不变、legacy 行为可证一致、seam 语义显式可审计，符合 M033 一类工程综述“几何 QEM 排序固定 3D placement，属性合法性做显式局部策略”的建议，也与 M004/085 的 4×4 line-quadric 主干兼容。当前的已知边界是：纹理保护启用时，可选的固定拓扑质量精修轮暂被跳过（该顶点重定位阶段尚未约束 UV 失真）。
