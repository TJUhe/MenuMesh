1. 学习方法与完成标准

不要按文件大小或目录顺序阅读。每次只选择一个 gtest，让测试输入限定问题范围，再沿这一条调用链进入源码。

读测试输入与 options -> 不运行，先预测 FeatureAnalysis -> 只运行一个 gtest -> 在相关阶段单步调试 -> 观察 CandidateEdge / TraceGraph / FeatureAnalysis -> 生成 debugUtil HTML -> 对照断言解释结果 -> 写半页案例总结

每个案例必须回答的五个问题

  1. 输入网格的顶点、面和 edge-face incidence 是什么？
  2. 该案例启用了哪些 evidence source，关闭了哪些 source？
  3. 哪些候选边进入了 FeatureGraph，哪些进入了 TraceGraph？
  4. 最终得到 open chain、closed loop、primitive、component 或 patch 中的哪些结构？
  5. 最后的断言是在验证算法正确性、鲁棒性，还是仅验证诊断字段？
完成标准：你能在不看断言的情况下预测主要计数，并能指出计数在哪个阶段发生变化。只会让测试通过，不等于已经理解该案例。

2. Debug 构建与 VS Code 启动

2.1 配置 Debug 测试程序

cmake -S . -B build/mingw-ninja-debug -G Ninja -DCMAKE_BUILD_TYPE=Debug -DCMAKE_C_COMPILER=gcc -DCMAKE_CXX_COMPILER=g++ -DMANUMESH_BUILD_TESTS=ON -DMANUMESH_ENABLE_DEBUG_UTIL=ON

cmake --build build/mingw-ninja-debug --target manumesh_tests --parallel
必须检查缓存：目录名包含 debug 不代表 debugUtil 已开启。运行 rg "MANUMESH_ENABLE_DEBUG_UTIL" build/mingw-ninja-debug/CMakeCache.txt，结果必须为 ON。此外，Release 构建定义了 NDEBUG，宏仍会成为 no-op。

2.2 使用 VS Code 过滤调试

仓库已经提供 (MinGW Ninja) Debug Unit Tests Filter。在“运行和调试”中选择它，按 F5 后输入完整测试名：

FeatureDetection.ClassifiesBoundaryEdgesOnOpenTriangle

该配置运行 build/mingw-ninja-debug/bin/manumesh_tests.exe，参数为 --gtest_filter=<测试名>，工作目录是仓库根目录。

2.3 不进调试器时的快速运行

$tests = ".\build\mingw-ninja-debug\bin\manumesh_tests.exe"
& $tests "--gtest_filter=FeatureDetection.DihedralThresholdControlsCreaseEdges" --gtest_break_on_failure

单元 0：先跑通 API 和调试器

FeatureDetection.FeatureNamespaceApiIsProjectScoped

测试位置：feature_detection_api_tests.cpp:31

学习目标认识 FeatureOptions、FeatureDetector、FeatureAnalysis 和自由函数入口。

断点FeatureDetector::analyze、detectFeatureCurves、FeatureDetectionPipeline::run。

完成标准能解释对象入口与自由函数为何得到相同结果，并能独立切换 gtest filter。

单元 1：最小拓扑证据

FeatureDetection.ClassifiesBoundaryEdgesOnOpenTriangle FeatureDetection.ClassifiesNonManifoldEdgesSeparately

测试位置：feature_detection_discrete_tests.cpp:140、192

学习目标一侧邻面是 boundary；超过两侧邻面是 non-manifold；二者都是拓扑证据，不依赖曲率。

断点collectFeatureEdges、BoundaryEvidenceStrategy::classify、NonManifoldEvidenceStrategy::classify。

观察context.edges、info.faces.size()、CandidateEdge::boundary/nonManifold。

练习先预测单三角形应产生几条 boundary edge，再运行验证。

单元 2：有向二面角、凸脊与凹谷

FeatureDetection.DihedralThresholdControlsCreaseEdges FeatureDetection.ClassifiesRightAngleConvexRidgePerEdge FeatureDetection.ClassifiesRightAngleConcaveValleyPerEdge

学习目标理解 featureAngleDeg、面绕向协调、angleRad 和 signedKind。

断点harmonizeFaceWindings、computeOrientedDihedralAngle、DihedralEvidenceStrategy::classify。

观察dihedralThreshold、dihedral.angleRad、dihedral.signedKind、analysis.convexFeatureEdges。

进阶随后运行 FeatureDetection.DetectsKnifeEdgeFoldBeyondNinetyDegrees 和 HarmonizesInconsistentWindingOnFlatSurface。

单元 3：FeatureGraph 与 TraceGraph

FeatureDetection.SplitsBranchedFeatureGraphAndMarksJunctions FeatureDetection.TracesShallowDihedralLoopAtRequestedAngle FeatureDetection.ReportsUntracedDihedralEdgesWhenTraceAngleIsStricter

学习目标被识别为 evidence 的边不一定进入 trace；loopTraceAngleDeg 决定二面角边是否参加 loop ownership。

断点initializeFeatureGraph、buildTraceGraph、finalizeFeatureGraphMarkers。

观察analysis.graph.edges、trace.graphEdges、tracedFeatureEdges、untracedFeatureEdges、顶点 degree。

完成标准能解释“有 feature edge 但没有 loop”为什么不是矛盾。

单元 4：从图恢复 chain、cycle 与 loop

FeatureDetection.DetectsCircularCylinderBoundaryLoops FeatureDetection.RecoversCircularLoopFromBranchedFeatureGraph FeatureDetection.RecoversPolygonalCycleThroughMultipleJunctions

学习目标掌握五段恢复顺序：junction circle、small cycle basis、remaining trace、primitive component、circular cluster。

断点recoverFeatureLoops 的五次调用、addTracedLoop、addRecoveredCycle、assignLoopToVertices。

观察loopId、TraceLoopStats、analysis.loops、loop.closed、graph.vertices[id].loopIds。

可视化在 graph、cleanup 和 loop recovery 后各输出一次 MANUMESH_DEBUG_UTIL_FEATURES，比较绿色 loop 何时出现。

单元 5：primitive 拟合

FeatureDetectionPrimitiveFit.TaubinMatchesExactCircleUnderNonUniformSampling FeatureDetectionPrimitiveFit.HalirFlusserRecoversEllipseUnderNonUniformSampling

学习目标先把图恢复隔离出去，单独理解 PCA 平面、Taubin 圆、Halíř-Flusser 椭圆、回退和 residual。

断点fitPrimitive、measurePrimitiveFitErrors、classifyPrimitiveFit、applyPrimitiveFit。

观察radius、majorRadius、minorRadius、axisRatio 和各种 RMS/max error。

单元 6：normal tensor 弱 crease

ManuMesh.NormalTensorScoresSeparatePlaneFromRidge ManuMesh.NormalTensorAddsFeatureEdgesWhenDihedralThresholdIsStrict ManuMesh.NormalTensorPersistenceRequiresSignificantScaleSupport

测试位置：simplification_normal_tensor_tests.cpp:79、101、147

学习目标理解面法向外积张量、特征值差、crease tangent、多尺度平滑和 persistence。

断点analyzeNormalTensor、computeNormalTensorFeaturesCached、normalTensorEdgeCandidate。

观察surfaceSaliency、creaseSaliency、cornerSaliency、persistentFeatureScore、edge/tangent alignment。

关键区别顶点有 tensor 分数只是诊断；两端点通过 persistence 和 alignment 后，mesh edge 才成为可消费证据。

单元 7：smooth-curvature ridge / valley

FeatureDetection.SmoothCurvatureRejectsExactPlaneAndFindsSmoothBump FeatureDetection.SmoothCurvatureGraphRecoversLabeledGaussianRidge FeatureDetectionAnalytic.SphereAndCylinderProduceNoSmoothCurvatureFeatures FeatureDetectionAnalytic.TorusInnerSideProducesNoSmoothCurvatureFeatures

学习目标理解 k-ring、局部尺度归一化、三次 Monge patch、基本形式、主曲率、extremality 零交叉、cyclideness 和跨尺度投票。

阅读顺序先看 computeSmoothCurvatureFeaturesCached 总循环，再看 fitScale，最后看 classifyScaleCandidate；不要从文件第一行顺读。

观察ScaleEstimate、ScaleCandidate、selectedScale、persistentScales、signedKind、scaleStability。

完成标准能解释为何“曲率大”不等于“存在 ridge/valley 特征线”，以及 sphere/cylinder/torus 为什么是重要负样本。

单元 8：图级工程恢复与 surface patch

FeatureDetectionCleanup.StrengthFilterKeepsLongWeakLinesAndStrongBranches FeatureDetectionUpgrade.ConsolidationBridgesOnlyCompatibleComponents FeatureDetectionUpgrade.JunctionsExposeBranchContinuationPairs FeatureDetectionUpgrade.CappedCylinderPartitionsIntoSideAndCapPatches

学习目标理解 weak spur 删除、局部 gap bridge、跨 component consolidation、junction continuation 以及 feature barrier flood fill。

断点cleanupTraceGraph、compatibleFeatureEvidence、consolidateFeatureGraph、finalizeFeatureGraphMarkers、buildFeaturePatches。

注意consolidation 的白盒测试直接调用内部函数，不代表单次完整 detector 一定产生 bridge；是否触发取决于图中真实存在的跨 component 缺口。

单元 9：真值 benchmark 与 QEM 消费

FeatureDetection.FixtureBenchmarkUsesCoaxialHoleGroundTruthLabels ManuMesh.QEMSimplifierConsumesPrecomputedFeatureAnalysis SimplificationAnalytic.DetectAndSimplifyPipelineIsByteStableAcrossRuns

学习目标学习 edge/junction 真值标签、precision/recall/closure，并理解检测结果怎样转成 FeatureGuidance 和简化约束。

断点benchmarkFeatureAnalysis、buildFeatureGuidanceFromAnalysis、effectiveFeatureProtectionMode、collapse feature constraint。

可视化识别后使用 FEATURES，简化后使用 BEFORE_AFTER；不要用 HTML 图代替 benchmark 数值。

5. debugUtil 使用指南

debugUtil 是 Debug-only 本地 HTML 线框工具。它用于定位网格、特征边、loop、异常边和简化差异，不是正式 viewer，也不属于 SDK API。

5.1 开启条件

  • CMake 必须配置 -DMANUMESH_ENABLE_DEBUG_UTIL=ON。
  • 必须是非 NDEBUG 的 Debug 构建。
  • 内部源码由 CMake force-include debugUtil/debugUtil.h，可直接使用宏。
  • 未满足条件时所有宏静默展开为 ((void)0)。

5.2 推荐环境变量

$env:MANUMESH_DEBUG_UTIL_DIR = "$PWD\output\debugUtil"
$env:MANUMESH_DEBUG_UTIL_OPEN = "0"
$env:MANUMESH_DEBUG_UTIL_MAX_EDGES = "50000"

OPEN=0 可防止一次 gtest 打开多个页面。每次调用仍会在标准错误输出中打印 HTML 路径。未设置目录时，默认写到 %TEMP%\manumesh-debugUtil。

5.3 常用宏

MANUMESH_DEBUG_UTIL_WIREFRAME("input_mesh", mesh);

MANUMESH_DEBUG_UTIL_FEATURES("feature_detection", mesh, analysis);

MANUMESH_DEBUG_UTIL_EDGE_LABEL(
    "candidate_edge", mesh, a, b,
    manumesh::debugUtil::UseCase::Candidate,
    "edge being checked");

MANUMESH_DEBUG_UTIL_BEFORE_AFTER(
    "simplify_before_after", input, simplified);

5.4 特征识别中的阶段快照

临时调试时可以在 FeatureDetectionPipeline::run() 中插入快照；诊断完成后应删除临时插桩：

featureGraph_.run(context);
MANUMESH_DEBUG_UTIL_FEATURES("03_graph", mesh, context.analysis());

cleanup_.run(context);
MANUMESH_DEBUG_UTIL_FEATURES("04_cleanup", mesh, context.analysis());

consolidation_.run(context);
MANUMESH_DEBUG_UTIL_FEATURES("05_consolidation", mesh, context.analysis());

loopRecovery_.run(context);
MANUMESH_DEBUG_UTIL_FEATURES("06_loops", mesh, context.analysis());
图像解释：showFeatures 同时绘制公共 FeatureGraph 和已恢复 loop。cleanup 从活动 TraceGraph 移除边时，公共图中的边保留但会标为 removedByCleanup，便于诊断来源与最终活动状态。

5.5 颜色语义

显示UseCase / 来源含义
灰色Mesh基础线框
蓝色Boundary开放边界
橙色Feature普通强特征；当前 smooth-curvature 也可能落入此色
紫色WeakFeaturenormal-tensor-only 弱特征
绿色FeatureLoop恢复后的可见 loop
青色Candidate候选或 cleanup bridge
黄色Warning被 cleanup 移除或可疑的边
红色Error / Rejected非流形错误或被拒绝的候选
不要只凭颜色判断 evidence source：当前 useCaseForFeatureEdge() 没有给 smooth-curvature 独立配色。需要同时检查 FeatureGraphEdge::smoothCurvature、normalTensor 和 dihedral 标志。

5.6 debugUtil 与 gtest 的职责边界

  • gtest 负责可重复的数值、拓扑和语义断言。
  • debugUtil 负责回答“错误发生在模型的什么位置”和“图在哪个阶段发生变化”。
  • HTML 带时间戳，不应提交为测试基线。
  • 大网格优先画单边或少量 overlay，不要在循环中无条件输出全量线框。
