ManuMesh Commercial Kernel Documentation

ManuMesh is a C++17 faceted mesh geometry kernel focused on additive-manufacturing mesh analysis and constrained mesh simplification. This guide is written as a delivery document for SDK consumers, integrators, QA engineers, and kernel developers.

1. Kernel Scope

ManuMesh provides a reusable geometry-processing kernel for triangular surface meshes. It is designed for applications that need robust mesh simplification, feature evidence extraction, topology-aware edge collapse, and SDK-level integration into manufacturing or inspection software.

Commercial positioning: the current release is a mesh kernel, not a full B-Rep CAD kernel. It operates on STL/OBJ-style triangle data and infers manufacturing features from tessellated geometry.
Capability Status Delivery meaning
Mesh storage, IO utilities, topology queries Implemented Public C++ mesh types and internal topology helpers are usable by SDK examples and tests.
Feature evidence and feature loop recovery Implemented Boundary, dihedral, non-manifold, local-scale normal-tensor evidence and primitive loop classification are available.
QEM / line-quadrics simplification Implemented Edge-collapse simplification with plane quadrics, line quadrics, feature-curve quadrics, and diagnostic reports.
Industrial legality gates Implemented Topology, boundary, normal deviation, triangle quality, local error, and local self-intersection filters.
Global tolerance envelope / certified Hausdorff bounds Partial Local error and sampled distance metrics exist; global certification should be added before safety-critical use.
B-Rep modeling, Boolean operations, offset, shape healing Roadmap Out of scope for this mesh-kernel delivery; should be documented as separate kernel modules if implemented.

2. Module Map

The SDK follows a modular structure similar to mature CAD kernels: stable public headers are separated from implementation details, and command-line tools consume the public API instead of owning algorithm logic.

Core

Defines mesh exchange types, status objects, topology caches, and mesh generators. Public headers live in include/core.

Feature Detection

Produces FeatureAnalysis from triangle meshes: feature edges, loops, primitive fits, tangents, local tensor scale, persistence, and diagnostics.

Simplification

Runs QEM / line-quadrics edge collapse with feature policies and hard legality filters. Public headers live in include/algorithms/simplification.

C ABI

Provides opaque handles, explicit struct initialization, and ABI versioning for non-C++ or compiler-boundary integrations.

CLI

The manumesh executable demonstrates SDK workflows, generates validation output, and supports automation.

Validation

GoogleTest, CTest, fixture meshes, external STL/OBJ data, and metrics output form the acceptance basis for delivery.

3. Architecture

ManuMesh is organized around a narrow dependency direction. Core data structures are the foundation. Feature detection consumes core mesh data. Simplification may consume feature analysis, but feature detection must not depend on simplification.

core -> feature_detection -> simplification core + common/detail -> feature_detection -> simplification applications -> public SDK headers -> C ABI when compiler or language boundaries require it

Run-Time Pipeline

Mesh -> validate input -> analyze feature evidence -> build initial plane / line / boundary / feature quadrics -> initialize dynamic topology and candidate queue -> solve edge-collapse placements -> apply feature, boundary, topology, normal, quality, error, and intersection gates -> update topology and queue -> compact result and emit SimplifyReport

Design Contracts

  • QEM and line quadrics rank collapse candidates; they do not replace hard legality checks.
  • FeatureAnalysis is a reusable semantic support layer, not a private detail of the simplifier.
  • The CLI is a consumer of the SDK, not the owner of kernel behavior.
  • Public C++ types should remain stable and documented; algorithm internals stay in src/.../detail.
  • New production filters must report their first-rejection counters in SimplifyReport.

4. Mesh Data Model

The kernel works on indexed triangle meshes. The main C++ type manumesh::Mesh stores vertices and triangular faces and is intended for in-process C++ SDK consumers. For ABI-sensitive integration, use PlainMesh or the C API.

Type Purpose Recommended use
Mesh Eigen-backed mesh convenience type. C++ clients built with compatible compiler and ABI settings.
PlainMesh Eigen-free exchange type. Clients that want C++ ergonomics without exposing Eigen in exchange structs.
MeshTopology Cached topology queries for boundary and non-manifold analysis. SDK users that need read-only topology diagnostics.
ManuMeshMeshHandle C ABI opaque mesh handle. C, C#, Python bindings, plugins, and binary-boundary integrations.
STL and OBJ meshes do not carry B-Rep semantics. Circles, holes, fillets, pockets, and patch boundaries are inferred from tessellation evidence and should be validated for the target data source.

5. Feature Detection

The feature module converts low-level mesh evidence into an explicit feature graph and loop-level descriptors. This layer is designed to be consumed by simplification today and by repair, remeshing, or validation modules in future releases.

Evidence Sources

Evidence Meaning Main risk
Boundary Edge with only one adjacent face. Open mesh boundaries may be intentional or defects.
Dihedral Adjacent face normals exceed the angle threshold. Threshold depends on tessellation and noise.
Non-manifold Edge has more than two adjacent faces. Often signals invalid input, not a design feature.
Normal tensor Local normal distribution suggests crease or corner saliency. Local edge scale, smoothing, multi-scale persistence, and minimum persistent scales dominate weak-feature behavior.

Feature Analysis Output

  • FeatureEdge: classified edge evidence and source counters.
  • FeatureLoop: recovered chain or loop with closure, primitive type, fit errors, and loop statistics.
  • VertexFeature: per-vertex feature ownership, tangent, circle data, and ellipse data.
  • Diagnostics: boundary, dihedral, normal-tensor, non-manifold, convex, concave, unknown edge counts, traced/untraced edges, tensor scored vertices, persistent score, local scale, and persistence.

Primitive Recovery

Closed loops can be classified as circle, near-circle, ellipse, or polygonal loop. Primitive fitting is intentionally limited to tessellated feature supports; it is not a replacement for exact CAD feature recognition.

6. QEM Simplification

The simplification module is a constrained edge-collapse pipeline. It uses Quadric Error Metrics for geometric ranking, line quadrics for tangential regularization, and explicit filters for production safety.

Plane QEM

A face plane can be expressed as n^T x + d = 0. The squared point-to-plane error is accumulated as a homogeneous quadric: 

E_plane(x) = (n^T x + d)^2
           = [x, 1]^T (p p^T) [x, 1]

Plane quadrics keep the simplified mesh close to local tangent planes. In near-flat regions they may be underconstrained in tangential directions, which is why the kernel also supports line quadrics.

Line Quadrics

A line quadric penalizes the distance from a placement to a local support line. It behaves as a small regularizer that improves candidate ordering and placement stability where plane QEM has weak tangential constraints. 

E_total = E_plane
        + lambda_line * E_line
        + lambda_boundary * E_boundary
        + lambda_feature * E_feature_curve

Collapse Acceptance

Gate Report field Delivery purpose
Feature policy featureRejectedCollapses Protect primitive loops, junctions, and minimum loop vertices.
Boundary policy boundaryRejectedCollapses Prevent unwanted open-boundary merging or removal.
Topology link condition topologyRejectedCollapses Preserve local topological consistency during collapse.
Normal deviation normalFlipRejectedCollapses Avoid foldover and severe local orientation changes.
Triangle quality qualityRejectedCollapses Reject triangles below the configured quality threshold.
Local error errorRejectedCollapses Reject collapses exceeding the configured local distance budget.
Local self-intersection selfIntersectionRejectedCollapses Avoid newly introduced intersections against active nearby faces.

Recommended Industrial Preset

manumesh::simplification::SimplifyOptions opt;
opt.targetRatio = 0.25;
opt.useLineQuadrics = true;
opt.lineWeight = 1e-3;
opt.weightMode = manumesh::simplification::WeightMode::Dihedral;
opt.featureBoost = 0.05;
opt.preserveFeatureCurves = true;
opt.featureProtectionMode =
    manumesh::simplification::FeatureProtectionMode::PrimitiveCurves;
opt.featureCurveWeight = 0.05;
opt.maxFeatureCurveDeviationRatio = 0.02;
opt.maxNormalDeviationDeg = 60.0;
opt.minTriangleQuality = 0.05;
opt.maxLocalErrorRatio = 0.02;
opt.preventLocalIntersections = true;
The preset is conservative. For aggressive decimation, acceptance should be based on SimplifyReport, metrics CSV output, and visual review of representative production meshes.

7. Public C++ API

The public API is intentionally small. Users configure an option struct, call a stateless convenience function or a reusable object facade, and inspect a report.

Minimal Simplification Example

#include "core/Mesh.h"
#include "algorithms/simplification/QEMSimplifier.h"

manumesh::Mesh input = loadUserMesh();

manumesh::simplification::SimplifyOptions options;
options.targetRatio = 0.25;
options.useLineQuadrics = true;
options.preserveFeatureCurves = true;

manumesh::simplification::SimplifyReport report;
manumesh::simplification::QEMSimplifier simplifier(options);
manumesh::Mesh output = simplifier.simplify(input, &report);

Feature Analysis Example

#include "algorithms/feature_detection/FeatureDetector.h"

manumesh::feature::FeatureOptions featureOptions;
featureOptions.featureAngleDeg = 40.0;
featureOptions.useNormalTensorFeatures = true;

manumesh::feature::FeatureDetector detector(featureOptions);
manumesh::feature::FeatureAnalysis analysis = detector.analyze(input);

PlainMesh Entry Point

#include "algorithms/simplification/PlainSimplifier.h"

manumesh::PlainMesh plainInput = getPlainMeshFromHost();
manumesh::simplification::SimplifyReport report;
manumesh::PlainMesh plainOutput =
    manumesh::simplification::simplifyPlainMesh(
        plainInput, options, &report);

8. C ABI

The C ABI is the preferred boundary for plugins, other languages, or clients that cannot share the same C++ compiler and standard-library ABI. All public C structs must be initialized before use.

Rule Reason
Call the matching *_init function for every public C struct. Sets ABI version, struct size, and default values.
Do not allocate or free opaque handles manually. The library owns handle lifetime and internal representation.
Pass caller-owned buffers when copying mesh data out. Avoids allocator mismatch across module boundaries.
Check returned status values instead of expecting exceptions. C clients need explicit error paths and stable status codes.

9. Build And Packaging

ManuMesh uses CMake and supports static or shared library builds. The recommended Windows development profile is MinGW + Ninja or a fully initialized Visual Studio developer environment.

MinGW + Ninja

cmake -S . -B build/mingw-release -G Ninja ^
  -DCMAKE_BUILD_TYPE=Release ^
  -DCMAKE_C_COMPILER=gcc ^
  -DCMAKE_CXX_COMPILER=g++ ^
  -DMANUMESH_EIGEN_PROVIDER=vendored ^
  -DMANUMESH_GOOGLETEST_PROVIDER=source

cmake --build build/mingw-release --parallel
ctest --test-dir build/mingw-release -LE performance --output-on-failure

SDK Install Layout

cmake -S . -B build/sdk-release -G Ninja ^
  -DCMAKE_BUILD_TYPE=Release ^
  -DCMAKE_C_COMPILER=gcc ^
  -DCMAKE_CXX_COMPILER=g++ ^
  -DMANUMESH_ENABLE_INSTALL=ON ^
  -DMANUMESH_INSTALL_CMAKE_CONFIG=ON

cmake --build build/sdk-release --target sdk-consumer-test --parallel
Installed path Contents
bin/ Runtime library and command-line executable.
include/ Public SDK headers.
lib/ Import or static libraries and optional CMake package files.
share/manumesh/ MSVC property sheet, vendored Eigen headers, and samples when enabled.

10. Validation

Delivery acceptance should be based on repeatable build, unit tests, ABI tests, external mesh fixtures, metrics, and visual inspection of generated STL files.

Regression Gate

cmake --build build/audit-mingw --target unit-tests --parallel
Latest local audit on 2026-07-09: 80 / 80 non-performance tests passed with the MinGW + Ninja release configuration.

External Model Gate

build/audit-mingw/bin/manumesh.exe validate-external --ratio 0.25 --samples 800

This command generates simplified STL outputs and metrics under tests/output/external_model_validation. Review at least:

  • final face count and termination reason;
  • mean and maximum sampled original-to-simplified distance;
  • minimum triangle quality and edge-length variation;
  • feature loops and primitive preservation diagnostics;
  • topology, normal, quality, error, and self-intersection rejection counters.

Acceptance Matrix

Area Required evidence Pass signal
Build Clean CMake configure and compile on the selected toolchain. All requested SDK, CLI, examples, and tests build.
API C++ and C ABI examples run without crashes or leaks visible to host tests. Examples and ABI tests pass.
Algorithm Fixture and external models reach target or report a meaningful blocking gate. terminationReason is explainable and diagnostics match parameter intent.
Geometry quality Metrics CSV plus visual STL inspection. No obvious holes, foldovers, unintended boundary merges, or severe sliver triangles under the acceptance preset.
Documentation This HTML, API headers, examples, and archived prototype notes. Integrator can build, call, validate, and diagnose the kernel without reading private source first.

11. Extension Policy

New capabilities should enter the kernel as parallel modules with explicit dependencies. Avoid turning the simplifier into a catch-all geometry engine.

Future module Recommended dependency Public contract
Repair core, common/detail, optional FeatureAnalysis Mesh validity repair, non-manifold cleanup, hole filling, boundary diagnostics.
Remeshing core, feature_detection Feature-aware isotropic or anisotropic remeshing.
Validation core, spatial indices, metrics Global Hausdorff, envelope checks, manufacturability reports.
Data exchange core STL/OBJ/glTF/PLY readers and writers with status reporting.
B-Rep bridge Separate geometry/topology model Should not be bolted onto the current triangle-only mesh type.

Contribution Rules

  1. Expose only stable SDK types under include.
  2. Keep implementation helpers under src/<domain>/detail.
  3. Add diagnostics for every production filter or recovery path.
  4. Write fixture tests for algorithm behavior and external tests for representative meshes.
  5. Document parameter intent and failure modes before promoting a feature to default behavior.

12. Boundaries

Commercial delivery documentation should be explicit about boundaries. Clear boundaries protect both the integrator and the kernel roadmap.

ManuMesh currently does not guarantee direct manufacturing tolerance compliance, full CAD feature-tree recovery, B-Rep validity, Boolean robustness, offset robustness, or global envelope certification.
Boundary Current behavior Mitigation
No B-Rep semantics in STL/OBJ Features are inferred from triangles. Validate on customer fixture meshes and keep primitive-fit thresholds explicit.
Weak features depend on scale Normal tensor scores are sensitive to smoothing and sampling. Use controlled parameter presets and compare before/after feature reports.
Aggressive simplification can harm triangle quality Low target ratios may force poor local candidates or rejection-limit termination. Enable quality, normal, local-error, and intersection gates for production presets.
Global error is sampled today Metrics provide evidence but not a formal certificate. Add a global envelope/Hausdorff module for certified downstream use.
