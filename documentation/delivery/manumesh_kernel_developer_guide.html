QEM 二次型展开速查：当前到底加了哪些项

ManuMesh 当前把所有软几何成本统一累积到齐次二次型。设 x 是候选新顶点位置，x_h=[x,1]^T，每个顶点保存 Q=[[A,b],[b^T,c]]，则候选代价为 E(x)=x_h^T Q x_h=x^T A x+2 b^T x+c。折叠边 (i,j) 时先做 Q_edge=Q_i+Q_j，placement 采用三级回退链（GH97）：先解全空间最优 A x=-b；若矩阵病态或解被拒绝，再求沿折叠边 a+t(b-a) 的一维最优（rank-2 直棱/边界折痕的良定情形，使用尺度不变的相对阈值）；最后才回退到端点/中点候选。边界边折叠另有 Lindstrom-Turk 边界守恒约束的投影（Placement.cpp::projectBoundaryPlacement）。

二次型项展开到 A,b,c参数与默认值作用与引用
面平面 QEMpi=[n,-n.p]，Q += area/3 * pi*pi^T。等价于 E=a(n.x-n.p)^2，所以 A+=a nn^T、b+=-a(n.p)n、c+=a(n.p)^2。无独立开关；退化面使用 1e-6 * representativeArea * pointQuadric，保持与正常 QEM 相同的 L^4 缩放量纲。主几何误差，来自 M002 Garland-Heckbert 1997。
普通 Line QuadriclineQuadric(p,n) 取两个与局部法线 n 垂直的单位方向 u,v，加入 Q_l=pi_u*pi_u^T+pi_v*pi_v^T。展开为 E_l=||(I-nn^T)(x-p)||^2，即惩罚切向漂移。useLineQuadrics=true，lineWeight=1e-3。默认分支：Q_i += w_i area_i Q_l。补平坦区 QEM 切向不满秩问题，来自 M004 Liu-Rahimzadeh-Zordan 2025。
特征加权 Line Quadric非 uniform 模式下 w_i=lineWeight+featureBoost*s_i；s_i 来自 dihedral、normal-tensor persistence、height 或 xband。normal-tensor 模式只给满足 normalTensorMinPersistentScales 的顶点写入 persistent score。weightMode=uniform，featureBoost=0.05；常用调试值 dihedral/normal-tensor + 0.08。featureAngleDeg=40，normalTensorFeatureThreshold=0.16，normalTensorScaleCount=1。让硬边、弱 ridge 或指定区域获得更高排序成本；feature evidence 参考 M007/M012/M013/M015/M016，弱特征参考 M026。
Adaptive Scale 分支若 adaptiveScale=true，placement 用干净的 adaptiveBaseLineWeight*area_i*Q_l line quadric（不再被 featureBoost 放大）；featureBoost 改为逐顶点队列优先级因子 priorityScale_i=1+max(0,featureBoost)*s_i，只乘候选排序代价（取折叠两端点的 max），不进入 quadric 或 placement 求解（Wang 2008 优先级解耦）。adaptiveScale=false，adaptiveBaseLineWeight=1e-2。非 adaptiveScale 路径保持旧行为。把"特征敏感排序"与"几何 placement"解耦，参考 M029 Wang 2008 feature-sensitive metric；用于跨尺度模型的 line weight 可比性。
边界 Plane Quadric边界边 (a,b) 只有一个邻接面时，取 m=normalize(n_face x e_hat)，加入 Q_b=boundaryWeight*|e|^2*pi_m*pi_m^T 到两个端点。它的 A=boundaryWeight*|e|^2*mm^T，秩 1；边长平方使该项与面积加权 face QEM 同为 L^4 缩放量纲。boundaryWeight=0.0 默认关闭；常用 1-10。硬边界保护另看 preserveBoundary。减少开放边界沿面内法向漂移；扩展 QEM 思路参考 M003，工程 guards 参考 M030-M033。
特征曲线 Tangent-Line Quadric当检测到 loop/primitive 后，对特征顶点用切线 t 调用 lineQuadric(p,t)，即 E_curve=eta*rho*area*||(I-tt^T)(x-p)||^2。这里 rho=0.35+0.65*confidence。preserveFeatureCurves=false 默认关闭；featureCurveWeight=0.05，常用 0.08；featureComponentMinConfidence=0.35 只影响 high-confidence component 报告计数，不过滤 component 或保护。允许沿特征线滑动，惩罚离开曲线；组合 M004 line quadrics、M016 CAD feature line、M026 weak-feature consolidation、M028/M029 feature-preserving simplification。
Primitive 投影与硬过滤圆/椭圆/多边形不是当前 Quadrics.cpp 里的单独径向二次型；当前代码用 tangent-line quadric 排序，再由 projectToCircle/projectToEllipse/projectToPolygonal、maxFeatureCurveDeviationRatio 和 featureProtectionMode 控制最终位置与是否拒绝折叠。maxFeatureCurveDeviationRatio=0 表示关闭曲线漂移预算；featureProtectionMode=PrimitiveCurves。圆/椭圆阈值默认均为 0.05。把“软成本排序”和“硬合法性保护”分开，符合 M030-M033 edge-collapse 工程建议。
带合理参数的数值展开例子

为了看清量级，假设坐标单位是 mm，某顶点 p=(10,5,0)，barycentric 顶点面积 a_i=2.0，候选新位置写作 x=(x,y,z)。实际折叠候选会把两端点 Q_i+Q_j 相加；下面先看单个顶点的一项怎样进入 A,b,c。

例子代入参数展开后的二次型读法
面平面 QEM平面 z=0，n=(0,0,1)，a=2.0E_plane=2*z^2，A=diag(0,0,2)，b=(0,0,0)，c=0离开面法向 0.2 mm 的代价是 2*0.2^2=0.08。
普通 Line QuadriclineWeight=1e-3，n=(0,0,1)，a_i=2.0，所以 alpha=0.002E_line=0.002*((x-10)^2+(y-5)^2)，A=diag(0.002,0.002,0)，b=(-0.02,-0.01,0)，c=0.25切向漂移 1 mm 只加 0.002，它是稳定排序的小正则项，不应压过平面 QEM。
特征加权 Line QuadricweightMode=normal-tensor，persistent score s_i=0.6，lineWeight=0.001，featureBoost=0.08，得 w_i=0.001+0.08*0.6=0.049，alpha=0.098E_feature_line=0.098*((x-10)^2+(y-5)^2)，A=diag(0.098,0.098,0)，b=(-0.98,-0.49,0)，c=12.25同样 1 mm 切向漂移，代价从 0.002 升到 0.098，约 49 倍；这就是弱特征被 QEM 排序“看见”的方式。
边界 Plane Quadric边长 |e|=4，boundaryWeight=5，边界面内法向 m=(1,0,0)，得 alpha=20E_boundary=20*(x-10)^2，A=diag(20,0,0)，b=(-200,0,0)，c=2000边界沿面内法向漂移 0.2 mm 的代价是 20*0.2^2=0.8，明显比普通 line 正则强。
特征曲线 Tangent-Line Quadric切线 t=(0,1,0)，featureCurveWeight=0.08，component confidence 0.8，rho=0.35+0.65*0.8=0.87，alpha=0.08*0.87*2=0.1392E_curve=0.1392*((x-10)^2+z^2)，A=diag(0.1392,0,0.1392)，b=(-1.392,0,0)，c=13.92沿 y 方向滑动不罚，离开特征线横向/法向才罚；这是“允许沿孔边走，但不要偏离孔边”。

例如同一个候选位移 x=(11,5,0.2)：平面项给 0.08，普通 line 项只给 0.002，normal-tensor 特征加权 line 项给 0.098。所以默认 line quadric 是温和正则；一旦 feature score 和 featureBoost 介入，它才会变成明显影响 collapse 排序的特征保护成本。

因此当前总能量可读成：E = E_plane + E_line(weightMode) + E_boundary + E_feature_curve；拓扑、边界、特征保护、法向翻转、三角形质量、局部误差和自交检查不是二次型项，而是候选折叠通过 QEM 排序之后的硬过滤。开启 preserveTexture（默认关闭）时，排序还会追加标量项 textureWeight * E_uv_local，并新增 UV chart 配对/定向/面积硬过滤；该项不改变任何 A,b,c 的维度，也不进入 placement 求解（见 QEM Simplification 一节的 Texture-Aware 小节）。

读懂 ManuMesh 算法的推荐顺序

如果从零看当前实现，先读 特征识别实现全链路，再按需读 Feature Loop 构造详解；当前契约是九阶段 pipeline，加按需 normal filter、component consolidation、junction branch pairing 和可选 surface patches。本文负责交付 API、集成边界与全内核上下文。

  1. 先看数据流：Mesh -> MeshEdgeInfoMap -> FeatureAnalysis -> quadrics -> candidate queue -> legality gates -> SimplifyReport。
  2. 再看特征识别：FeatureDetector.cpp 固定九阶段调度；独立 normal/filter/compatibility/consolidation/segmentation/benchmark 单元把 evidence 变成 graph、branches、loop、component 和 patches。
  3. 最后看简化消费：FeatureConstraints.cpp 决定哪些 collapse 被拒绝，Quadrics.cpp 决定 feature curve soft quadric 如何加权，feature_components、graph_cleanup_*、feature_rejected、quality_rejected、error_rejected 解释算法为什么这样停。

1. Kernel Scope

ManuMesh provides a reusable geometry-processing kernel for triangular surface meshes. It is designed for applications that need robust mesh simplification, feature evidence extraction, topology-aware edge collapse, and SDK-level integration into manufacturing or inspection software.

Commercial positioning: the current release is a mesh kernel, not a full B-Rep CAD kernel. It operates on STL/OBJ-style triangle data and infers manufacturing features from tessellated geometry.

The SDK follows a modular structure similar to mature CAD kernels: stable public headers are separated from implementation details, and command-line tools consume the public API instead of owning algorithm logic.

Defines mesh exchange types, status objects, topology caches, and mesh generators. Public headers live in include/core. 本轮新增公共工具头 core/Tolerances.h（统一退化三角形容差族， 如 kMinTriangleArea=1e-24、kMinNormalLength）与 core/MathConstants.h（kPi）； MeshGenerators.h 新增闭流形共享顶点立方体 generateClosedCubeGrid(n, size)。

3. Architecture

ManuMesh is organized around a narrow dependency direction. Core data structures are the foundation. Feature detection consumes core mesh data. Simplification may consume feature analysis, but feature detection must not depend on simplification.

core -> feature_detection -> simplification core + common/detail -> feature_detection -> simplification applications -> public SDK headers -> C ABI when compiler or language boundaries require it debugUtil -> internal implementation files only -> disabled in normal builds and SDK delivery

Run-Time Pipeline

Mesh -> validate input -> analyze feature evidence -> build initial plane / line / boundary / feature quadrics -> initialize dynamic topology and candidate queue -> solve edge-collapse placements -> apply feature, boundary, topology, normal, quality, error, intersection, and optional texture-chart gates -> update topology and queue -> compact result and emit SimplifyReport

Design Contracts

  • QEM and line quadrics rank collapse candidates; they do not replace hard legality checks.
  • FeatureAnalysis is a reusable semantic support layer, not a private detail of the simplifier.
  • The CLI is a consumer of the SDK, not the owner of kernel behavior.
  • Public C++ types should remain stable and documented; algorithm internals stay in src/.../detail.
  • New production filters must report their first-rejection counters in SimplifyReport.

Texture Coordinates (Corner-Owned UV)

本轮数据模型新增了逐面逐角纹理坐标。Vec2 是 Eigen::Vector2d 的公开别名；FaceTexCoords 为一个三角形保存 std::array<Vec2, 3> uv 与 bool valid 标记。Mesh::faceTexCoords 为空表示网格没有纹理坐标；非空时必须与 Mesh::faces 按面对齐，其中个别条目可以是 invalid（对应 OBJ 中未贴图的面， textured/untextured 相邻面之间的过渡在简化阶段按受保护的 chart 边界处理）。Mesh::hasTextureCoordinates() 在至少一个面拥有有效逐角坐标时返回 true。

UV 采用"角拥有"（corner-owned）而不是"顶点拥有"语义：一个几何顶点可以同时属于多个 UV chart，纹理接缝（seam）两侧的角在同一个顶点上保留各自不同的坐标。 顶点拥有的 UV 无法表达 seam，这正是简化阶段局部 chart 保护策略成立的数据前提。

SDK 边界与 IO 行为

  • Eigen-free SDK 边界：PlainVec2 { double u, v; }、PlainFaceTexCoords 与 PlainMesh::faceTexCoords 与内部类型一一对应；toMesh / toPlainMesh 双向转换以及 compaction、validation、索引 remap 均已支持纹理数据。
  • OBJ 读取（loadObj）由"简单三角网格"升级为"多边形网格"：严格凸面保持确定性 fan 顺序，凹面先按主法向投影再做 ear clipping，并为三角化后的每个角点保留原始 vt 索引；重复位置、退化轮廓、自交轮廓以及同一个面混用贴图角与未贴图角都会作为格式错误被拒绝。
  • 公开导出路径当前仍是 ASCII STL（saveAsciiStl），STL 格式本身不携带 UV；带 UV 的结果应通过 C++ Mesh / PlainMesh 边界在进程内继续消费。
  • C ABI 未暴露纹理数据，详见 C ABI 一节。
STL and OBJ meshes do not carry B-Rep semantics. Circles, holes, fillets, pockets, and patch boundaries are inferred from tessellation evidence and should be validated for the target data source.

Smooth Curvature Evidence Path (Opt-In)

本轮新增了确定性光滑曲率特征检测，面向扫描件与自由曲面上的光滑 ridge/valley，不含任何神经网络或学习成分。实现位于 src/feature_detection/SmoothCurvature.cpp，权威设计文档为 documentation/design/smooth_curvature_feature_detection_2026_07_11.md， 文献综述见 documentation/papers/recent_deterministic_feature_detection_2026-07-11.md。

双证据路径理念

boundary、non-manifold、dihedral 边是离散网格上的不连续，属于硬证据； 光滑 ridge/valley 是局部光滑表面上的微分事件，属于弱证据。 把两类原始分数直接混合会让阈值难以解释，并让噪声与强拓扑证据直接竞争。 因此 ManuMesh 保持两条路径：硬证据路径（boundary / non-manifold / dihedral）与弱光滑证据路径（normal tensor 与多尺度 quadric 曲率）。两条路径只在显式 FeatureGraph 汇合，在那里 source ownership、连续性、junction、cleanup、component 与 confidence 统一提供给下游简化和未来的 remeshing 适配层。component 置信度把 normal-tensor 与 smooth-curvature 视为相互独立的弱支持，硬证据始终占主导。

算法（逐顶点、逐拓扑尺度）

  1. 构建 k-ring 邻域与面积加权局部法线；
  2. 用局部平均边长乘以 ring 数做坐标归一化；
  3. 带距离权与确定性 Huber 重加权拟合三次 Monge patch（9 系数：二次块承载曲率，三次块承载曲率导数）；
  4. 由第一/第二基本形式解广义自伴特征问题，得到两条带符号主曲率与主方向；
  5. 由三次项解析计算 extremality e_i = ∇κ_i · t_i，并用 Ohtake 边零交叉极值判据（邻居切向与 extremality 先做符号同步）确认中心是带符号的方向极值，才接受 ridge/valley 候选；
  6. 用尺度归一化曲率幅值、各向异性、极值对比度与拟合残差质量融合打分；
  7. 默认选择分数最高尺度；opt-in stable-scale 模式按跨尺度 sign/tangent/score 一致性选择并可拒绝低稳定性参考尺度。所有请求尺度独立投票，支持尺度不要求相邻，最粗尺度没有特殊否决权；
  8. 两端点在符号、切向、尺度支持、边对齐上都一致时，才把持久的顶点证据转成 mesh-edge 证据。

最终分数无量纲：对网格做均匀缩放不需要重新调曲率阈值。源码中的持久分数为 (0.65 * referenceScore + 0.35 * meanSupportedScore) * (persistentScales / scaleCount) * meanSupportedAlignment； averageFeatureScore 则是 supportedScoreSum / scaleCount，未支持尺度按零贡献。实现位置： SmoothCurvature.cpp:579-639。

弱边 materialization 还有两层容易漏看的门控：normal-tensor 与 smooth-curvature 都跳过任何接触强离散特征顶点的边，形成一个顶点宽的排除区；normal-tensor 的网格边方向对齐使用 max(|d·tA|, |d·tB|)，允许一端满足，而 smooth-curvature 使用 min(...) 并额外要求两端 tangent consistency，因此后者更严格。 直接位置：FeatureEvidence.cpp:330-430。

6. QEM Simplification

The simplification module is a constrained edge-collapse pipeline. It uses Quadric Error Metrics for geometric ranking, line quadrics for tangential regularization, and explicit filters for production safety.

Plane QEM

A face plane can be expressed as n^T x + d = 0. The squared point-to-plane error is accumulated as a homogeneous quadric: 

E_plane(x) = (n^T x + d)^2
           = [x, 1]^T (p p^T) [x, 1]

Plane quadrics keep the simplified mesh close to local tangent planes. In near-flat regions they may be underconstrained in tangential directions, which is why the kernel also supports line quadrics.

Line Quadrics

A line quadric penalizes the distance from a placement to a local support line. It behaves as a small regularizer that improves candidate ordering and placement stability where plane QEM has weak tangential constraints. 

E_total = E_plane
        + lambda_line * E_line
        + lambda_boundary * E_boundary
        + lambda_feature * E_feature_curve

Placement Solve, Fallback Chain, And Priority Decoupling

  • 三级 placement 回退链（GH97）：全空间最优解 A x = -b → 沿折叠边的一维最优（本轮新增，覆盖 rank-2 直棱/边界折痕的良定情形，使用尺度不变的相对阈值）→ 端点/中点候选（Quadrics.cpp）。
  • 边界边折叠 placement：采用 Lindstrom-Turk 边界守恒约束投影，实现在 src/simplification/Placement.cpp（projectBoundaryPlacement，自 FeatureConstraints 迁入并升级）。
  • 扩展 link condition："边界弦"（内部边、两端点均为边界顶点）一律拒绝折叠，防止开边界被捏合成非流形 pinch 点（CollapseTopology.cpp）。该检查与 preserveBoundary（默认 false）无关，始终生效。
  • Wang 2008 优先级解耦：adaptiveScale=true 时 featureBoost 不再放大 quadric，而是作为逐顶点队列优先级因子 priorityScale=1+featureBoost*score 只乘排序代价（取两端点 max）；placement 使用干净的 adaptiveBaseLineWeight（默认 1e-2）line quadric。非 adaptiveScale 路径保持旧行为。
  • 尺度不变相交谓词：局部自交检查使用相对容差 kRelativeIntersectionEps=1e-9（CollapseLegality.cpp、QualityRefinement.cpp）。

Texture-Aware Ranking And UV Chart Protection (Opt-In)

本轮为带逐角 UV 的网格新增了纹理感知能力。实现位于 src/simplification/TextureProtection.cpp 与 src/simplification/detail/TextureProtection.h，权威设计文档为 documentation/design/texture_aware_qem.md。核心决定是不做属性扩维： 几何 quadric 保持 Mat4（作用在齐次坐标 (x, y, z, 1) 上），纹理坐标既不追加进该向量，也不放大 placement 求解。对一次 edge-collapse 的候选位置 p，队列使用： 

E_total(p) = E_geometry_4x4(p) + textureWeight * E_uv_local(p)

其中 E_uv_local 是只在坍缩已触及的面上求值的标量；placement 候选仍然是既有的端点、中点与稳定 3D QEM 最优点，因此几何求解路径完全不变。

局部 chart 配对与拒绝规则

对坍缩两端点，用相对容差（textureSeamTolerance）网格哈希把入射角 UV 分组为局部 chart，再由坍缩边的入射面建立两端点 chart 之间的一一配对。 出现以下任一情况时坍缩被拒绝：

  • 一端的某个 chart 在另一端没有对应 chart；
  • 配对歧义，或配对会合并互不相关的 chart；
  • 任一存活 UV 三角形的有符号定向发生翻转；
  • 任一存活 UV 三角形的有符号面积低于旧面积的 minTextureAreaRatio 比例。

这套规则允许在双侧 seam 上坍缩——只要 seam 两侧的 chart 都一致配对； 跨 seam、或在 seam 顶点之外会合并 chart 归属的坍缩则被过滤。被接受的坍缩只更新受影响的存活面角， 不同配对 chart 在同一几何顶点上保留各自不同的合并 UV。

标量失真代价与尺度不变性

E_uv_local = edgeLength^2
             * sum(faceArea * cornerUvDisplacement^2)
             / meanLocalUvEdgeLength^2

面面积与边长因子让该项与面积加权几何 QEM 拥有相同的长度量纲； 除以局部 UV 边长尺度使结果对 UV atlas 的均匀缩放不变，因此 textureWeight 不需要随贴图分辨率或 atlas 缩放重新调参。

复杂度与文献定位

几何求解仍是由 4×4 齐次 quadric 支撑的固定 3D 求解；纹理工作只做期望 O(k) 的局部 chart 哈希与三角检查（k 为 one-ring 规模），随后是既有的优先队列工作。 没有全局参数化、atlas 遍历或属性空间矩阵分解，因此 edge-collapse 的渐近复杂度不变。文献上，Garland-Heckbert 的属性 QEM（M003）是把颜色/纹理纳入简化目标的历史参照； ManuMesh 采用现代 edge-collapse 管线文献（M033）建议的工程拆分——几何 QEM 排序固定的 3D placement，拓扑/特征/属性合法性作为显式局部策略——并与 4×4 line-quadric 主干（M004/085）保持兼容。

纹理保护当前只通过 C++ SimplifyOptions 暴露；CLI simplify 命令没有 --preserve-texture 之类选项，请勿在自动化脚本中假设其存在。

8. C ABI

The C ABI is the preferred boundary for plugins, other languages, or clients that cannot share the same C++ compiler and standard-library ABI. Input options must be initialized; report and stats outputs are initialized by capacity-aware calls.

Rule Reason
Call the matching *_init function for every public C struct. Sets ABI version, struct size, and default values.
Do not allocate or free opaque handles manually. The library owns handle lifetime and internal representation.
Pass caller-owned buffers when copying mesh data out. Avoids allocator mismatch across module boundaries.
Check returned status values instead of expecting exceptions. C clients need explicit error paths and stable status codes.
Expect MANUMESH_STATUS_OUT_OF_MEMORY on allocation failure. 本轮异常映射新增 std::bad_alloc → OOM 状态码，内存耗尽不再归入通用错误。
Pass finite numeric parameters. 数值参数现做 finite 校验：如 merge_relative_epsilon 必须有限且非负，否则返回 MANUMESH_STATUS_INVALID_ARGUMENT。
2026-07-15 size-aware 尾字段：ManuMeshSimplifyOptions 包含 smooth stable-scale、feature normal filter、graph consolidation 和 weak-spur controls；ManuMeshSimplifyReport 包含相应 stability/filter/consolidation 诊断，以及 winding/cleanup/recovery 字段。 转换器只读写 struct_size 覆盖到的字段，旧短结构仍兼容。C ABI 现场保护光滑特征时需同时设置 preserve_feature_curves = 1 与 use_smooth_curvature_features = 1。
纹理数据当前不经过 C ABI：include/api/CApi.h 顶部已明确声明 v1 ABI 不携带逐角纹理坐标。manumesh_mesh_set_data 与 manumesh_mesh_copy_vertices / manumesh_mesh_copy_faces 只交换顶点坐标与三角形索引， ManuMeshSimplifyOptions 也未包含 preserveTexture 等纹理字段。需要逐角 UV（faceTexCoords）的工作流请使用 C++ Mesh 或 Eigen-free 的 PlainMesh 边界；若未来在 C ABI 暴露纹理，应按既有规则新增带 *_init 的版本化结构体。

11. Extension Policy

New capabilities should enter the kernel as parallel modules with explicit dependencies. Avoid turning the simplifier into a catch-all geometry engine.

Future module Recommended dependency Public contract
Repair core, common/detail, optional FeatureAnalysis Mesh validity repair, non-manifold cleanup, hole filling, boundary diagnostics.
Remeshing core, feature_detection Feature-aware isotropic or anisotropic remeshing.
Validation core, spatial indices, metrics Global Hausdorff, envelope checks, manufacturability reports.
Data exchange core STL/OBJ/glTF/PLY readers and writers with status reporting.
B-Rep bridge Separate geometry/topology model Should not be bolted onto the current triangle-only mesh type.

Contribution Rules

  1. Expose only stable SDK types under include.
  2. Keep implementation helpers under src/<domain>/detail.
  3. Add diagnostics for every production filter or recovery path.
  4. Write fixture tests for algorithm behavior and external tests for representative meshes.
  5. Document parameter intent and failure modes before promoting a feature to default behavior.

12. Boundaries

Commercial delivery documentation should be explicit about boundaries. Clear boundaries protect both the integrator and the kernel roadmap.

ManuMesh currently does not guarantee direct manufacturing tolerance compliance, full CAD feature-tree recovery, B-Rep validity, Boolean robustness, offset robustness, or global envelope certification.
Boundary Current behavior Mitigation
No B-Rep semantics in STL/OBJ Features are inferred from triangles. Validate on customer fixture meshes and keep primitive-fit thresholds explicit.
Weak features depend on scale Normal tensor scores are sensitive to smoothing and sampling. Use controlled parameter presets and compare before/after feature reports.
Aggressive simplification can harm triangle quality Low target ratios may force poor local candidates or rejection-limit termination. Enable quality, normal, local-error, and intersection gates for production presets.
Global error is sampled today Metrics provide evidence but not a formal certificate. Add a global envelope/Hausdorff module for certified downstream use.
