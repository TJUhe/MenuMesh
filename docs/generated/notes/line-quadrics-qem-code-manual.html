1这份程序实现了什么

当前仓库实现的是一个基于边坍缩的三角网格简化库。它以 Garland-Heckbert 标准 QEM 为基础，加入 Liu、Rahimzadeh、Zordan 在 SGP 2025 论文中提出的 Line Quadrics 思想，用很小的线二次型权重改善标准 QEM 在平坦区域的退化排序问题。

从工程角度看，它现在有两层使用方式：

  • 动态库：目标名 line_quadrics_qem，外部 CMake 工程可以通过 find_package(line_quadrics_qem CONFIG REQUIRED) 使用。
  • CLI 程序：目标名 linequadrics，用于生成 demo 网格、简化 STL/OBJ、输出 metrics、做 sweep 实验和特征报告。
我对你原网页的判断

你给的 qem-line-quadrics-notes.html 对当前程序很有启发意义，因为它把“标准 QEM 的零误差平坦区”和“Line Quadrics 为什么能补上切向约束”讲成了同一个数学故事。当前程序的核心代码正是沿着这个故事组织的：先建立平面 quadric，再把顶点法线方向的 line quadric 作为正则项加进去。

2.2 边界项和特征曲线项的文献依据

当前程序项文献依据强度推荐引用说明
boundaryWeight 边界 plane quadric较直接Garland-Heckbert 1998；Garland 博士论文；CGAL Surface Mesh Simplification 文档这些资料都支持在边界/不连续处加入额外约束平面或 pseudo-faces，使边界顶点的 quadric 更强，减少边界漂移。
featureCurveWeight tangent-line quadric组合式依据Liu-Rahimzadeh-Zordan 2025；Vidal-Wolf-Dupont 2011；Jiao-Bayyana 2008；Hussain-Grahn-Persson 2008Line Quadrics 论文支持用 line quadrics 做可控/特征敏感简化；CAD 特征线检测论文支持先识别特征曲线；特征保持简化论文支持对特征边/点做硬约束或优先保护。本程序把这些思想组合成“沿特征切线的一维 line quadric + collapse 拒绝规则”。

2.3 当前程序不是论文的逐字逐句复刻

本程序复现了 Line Quadrics 对 QEM 的关键增强，但也加入了工程实验分支：

  • weightMode 提供 uniform、dihedral、height、xband 四种权重模式，用来观察不同区域权重如何影响简化。
  • boundaryWeight 增加边界 plane quadric，用来缓解边界漂移。
  • preserveFeatureCurves 增加特征 loop 检测、圆拟合、最小顶点数保护和圆投影。
  • 求解器对奇异矩阵使用端点/中点 fallback 候选集，优先保证程序稳定运行。

4公共 API 与数据结构

4.1 Mesh

namespace lq {
using Vec3 = Eigen::Vector3d;
using Mat4 = Eigen::Matrix4d;

struct Face {
  std::array<int, 3> v{};
};

struct Mesh {
  std::vector<Vec3> vertices;
  std::vector<Face> faces;
};
}

Mesh 是没有半边结构的简单三角网格容器。算法内部会临时构建边表、活动面、活动顶点、版本号和优先队列；公共 API 保持轻量，便于动态库调用。

4.2 SimplifyOptions

字段默认值作用
targetFaces-1目标面数；大于 0 时优先于比例。
targetRatio0.25目标面数比例。
useLineQuadricstrue是否启用普通 line quadric。
lineWeight1e-3普通 line quadric 基础权重。
weightModeUniform普通 line quadric 的区域增强模式。

4.3 SimplifyReport

SimplifyReport 用于观察算法行为，例如实际坍缩边数、拒绝坍缩次数、fallback 求解次数、检测到的特征 loop 数、圆形特征 loop 数、投影放置次数等。这些字段对调参很重要，因为不同输入网格的失败原因通常不在最终 STL 里，而在中间统计里。

6simplifyMesh 执行流程

核心流程如下：

simplifyMesh(input, options, report) 1. 如果 preserveFeatureCurves，先 detectFeatureCurves(input) 2. computeInitialQuadrics() - 面 plane quadric - 可选 boundary quadric - 可选 normal line quadric - 可选 feature tangent line quadric 3. 初始化 VertexState / FaceState 4. collectActiveEdges() 并构建优先队列 5. 循环直到 activeFaceCount <= targetFaces a. 弹出最低代价候选边 b. 检查版本号、端点活动状态、邻接关系 c. 合并端点 quadric，求解新位置 d. 特征约束检查 e. 圆形特征投影 f. 退化面/合法性检查 g. 写回顶点、重写面、删除退化面和重复面 h. 把受影响邻边重新压入队列 6. compactResult() 输出 Mesh

6.1 顶点状态

内部 VertexState 不只保存位置和 quadric，还保存：

  • active：顶点是否仍存在。
  • version：优先队列 stale candidate 检查。
  • isFeature、featureLoopId、circularFeature：特征约束。
  • curveTangent、circleCenter、circleNormal、circleRadius：特征曲线和圆投影。

6.2 候选边代价

对候选边 $(i,j)$，程序先合并 quadric：

$$Q_{ij}=Q_i+Q_j$$

再通过 solveOptimal 得到新位置 $x$ 和代价：

$$cost(i,j)=\bar{x}^{\top}Q_{ij}\bar{x}$$

优先队列按 cost 从小到大弹出，形成局部贪心简化。

7参数如何映射到算法项

当前程序最终可以理解为给每个顶点构造如下 quadric：

$$Q_i=Q_i^{plane}+Q_i^{normalLine}+Q_i^{boundary}+Q_i^{featureCurve}$$
参数进入的项代码含义
--method standard关闭 $Q_i^{normalLine}$只用标准 QEM 及用户显式开启的其他项。
--method line开启 $Q_i^{normalLine}$默认路径。
--line-weight W$W a_i Q_\ell(v_i,n_i)$法线方向 line quadric 强度。
--weight-mode dihedral$W+\beta s_i$硬边附近增加 line weight。
--weight-mode normal-tensor$W+\beta t_i$使用多尺度 normal tensor 特征分数调整 line weight，适合观察弱特征。
--boundary-weight G$G\|e\|Q_{boundary}$边界边添加额外支撑平面。
--preserve-feature-curves启用检测、约束、曲线项保护折痕/边界 loop，圆形 loop 会投影回圆。
--feature-curve-weight E$E a_i Q_\ell(v_i,\tau_i)$沿特征切线建立 line quadric。
--max-feature-curve-deviation-ratio Rcollapse legality filter拒绝让 feature loop 原始 placement 漂移超过 $R$ 倍 bbox 对角线的坍缩。
--max-local-error-ratio Rcollapse legality filter在坍缩前检查局部几何漂移，超过 $R$ 倍 bbox 对角线则拒绝。
--industrial-safe组合保护 preset启用边界保护、质量 guard、normal deviation guard、局部误差 guard 和局部自交检查。
lineWeight 不宜盲目放大

论文和本程序实验都把小权重作为合理起点，例如 1e-3。过大的 line weight 会让均匀采样和局部形状保持之间的平衡偏向正则项，可能牺牲几何误差。

9.2 C++ 调用

#include "line_quadrics_qem/Mesh.h"
#include "line_quadrics_qem/QEMSimplifier.h"

int main() {
  lq::Mesh input;
  std::string error;
  if (!lq::loadMesh("input.stl", input, &error)) {
    return 1;
  }

  lq::SimplifyOptions options;
  options.targetRatio = 0.2;
  options.lineWeight = 1e-3;

  lq::SimplifyReport report;
  lq::Mesh output = lq::simplifyMesh(input, options, &report);
  lq::saveAsciiStl("output.stl", output);
}

10有没有更好的论文方法

有。当前程序的边界项和 tangent-line 特征曲线项是一个轻量、容易集成进 QEM 的方案。如果要继续往工业软件方向走，可以按目标选择更强方法。

目标更强方法代表参考对当前程序的启发
边界保持更稳约束式边坍缩：把边界、feature edge 标成 constrained edge，不允许跨越或破坏约束边。CGAL Surface Mesh Simplification 的 constrained edges / placement filter；Hoppe 1996 Progressive Meshes 中的 discontinuity curves。比单纯加 boundaryWeight 更硬。可以新增 constrainedEdges 输入，边界边默认不跨边坍缩。
边界和体积同时保持Lindstrom-Turk memoryless simplification，用体积保持、边界面积保持、三角形形状优化作为约束序列。Lindstrom and Turk, Fast and Memory Efficient Polygonal Simplification, VIS 1998。适合加一个 PlacementPolicy，在 QEM placement 之外提供体积/边界约束 placement。
特征线识别更可靠不要只靠二面角；引入 CAD 特征线、C0/C1/C2 discontinuity、normal tensor、曲率多尺度检测。Vidal-Wolf-Dupont 2011；Jiao-Bayyana 2008；Tsuchie-Higashi 2014。当前 detectFeatureCurves 可替换为更强 detector，输出仍然是 feature vertices/loops/tangents。
特征保持更强特征边硬约束 + 特征边独立简化 + 曲面区域简化，再重建/缝合。Peyrot-Payan-Antonini 2014 aliasing-free simplification；Hussain-Grahn-Persson 2008 feature-preserving simplification。比 tangent-line soft constraint 更稳定，适合 CAD 模型：先简化 feature graph，再简化 patch interior。
特征敏感误差更统一把位置和法线一起放进高维 feature-sensitive metric，或用 normal-guided QEM。Wei and Lou 2010 feature sensitive metric；Zheng et al. 2014 normal-guided QEM denoising。可以把当前 lineWeight 扩展为“位置误差 + 法线误差 + 特征距离”的组合能量。
误差有硬保证Hausdorff envelope / tolerance volume；每次坍缩必须满足误差界。Hausdorff envelope surface simplification 文献；CGAL/工程库中的 placement filter 思路。工业精度要求高时，这是比 QEM 代价更可靠的验收层。QEM 可做候选排序，Hausdorff/tolerance 做硬过滤。

10.1 较新的圆孔识别/孔特征论文线索

论文/方向年份适合什么输入对当前程序的改进点
Yip, Stahl, Schellewald. Robust Hole-Detection in Triangular Meshes Irrespective of the Presence of Singular Vertices. Computer-Aided Design.2024三角网格当前程序把 feature loop 当作普通图连通分量处理。该方法专门解决 triangular mesh 的 hole/boundary traversal，尤其强调 singular vertices 下的 boundary 唯一性和 hole/main-boundary 分类。适合先替换当前 boundary loop 提取层。
Zhang et al. Multi-Scale and Irregularly Distributed Circular Hole Feature Extraction from Engine Cylinder Point Clouds. Computer-Aided Design.2024点云/工业扫描面向发动机缸体这种多尺度、不规则分布圆孔。可借鉴“多尺度候选 + 曲率中心/孔点聚集”的思路，改善小孔、缺点孔、密集孔识别。
Zhang et al. CHBS-Net: 3D Point Cloud Segmentation Network with Key Feature Guidance for Circular Hole Boundaries. Machines.2023点云/检测数据如果上游是扫描点云而不是 STL，先分割圆孔边界点，再拟合圆，比在简化后的三角网格上靠二面角找圆更稳。
Zhao. A Novel Computational Paradigm for Reconstructing Solid CAD Features from a Segmented Manifold Triangular Mesh. Applied Sciences.2024已分割三角网格从 mesh patch 中提取 cross-sectional sketches 和 feature paths，再用 Open CASCADE 重建实体特征。对圆孔来说，方向是从“识别边界圆”升级到“恢复参数化 CAD 特征”。
AAGNet / BrepMFR / BRepNet 系列 machining feature recognition2023-2024STEP/B-Rep如果能拿到原始 B-Rep，不建议从 STL 猜孔。直接在 face-edge graph 上识别 through hole、blind hole、counterbore、countersink 等加工特征，语义更强。
最推荐的当前程序改造顺序

对现有 STL/三角网格，优先引入 Yip et al. 2024 的 robust boundary/hole traversal，再在每个 hole boundary 上做加权圆/椭圆/RANSAC 拟合、平面一致性检查和 cylinder-axis 验证。若输入来自扫描点云，再考虑 CHBS-Net 或 2024 多尺度圆孔提取。若上游能提供 STEP，则直接走 B-Rep feature recognition，别从 STL 反推。

推荐演进路线

短期最划算的是保留当前 Line Quadrics 作为排序/正则项，同时增加 constrained-edge collapse 和 Hausdorff/tolerance filter。中期再把 detectFeatureCurves 换成 normal tensor 或 CAD discontinuity detector。长期如果要处理真正 CAD/B-Rep 风格模型，最好走“特征图先简化、面片内部再简化、最后约束缝合”的 patch-aware pipeline。

11可参考的 GitHub 项目

这些项目不一定适合直接引入依赖，但很适合拆开借鉴架构、算法模块和测试方式。

项目方向最值得借鉴的点注意事项
Mauhing/hole-detection-on-triangle-mesh三角网格孔洞/边界检测和 Yip et al. 2024 配套，重点处理 singular vertices 下的 boundary traversal、complex boundary decomposition、hole/main-boundary 分类。最适合改进当前圆孔候选 loop 提取。Python 参考实现。建议移植算法思想到 C++，不要直接作为运行时依赖。
CGAL/cgal工业级几何算法库Surface Mesh Simplification 的 policy-based 设计、constrained edges、placement filter、Garland-Heckbert 和 Lindstrom-Turk cost/placement。适合重构当前 simplifier 架构。许可证和依赖较重；可先借鉴接口设计，不一定直接引入。
OpenMesh半边网格与 decimation frameworkDecimater module 设计：每个模块提供 collapse_priority / legality，以插件方式组合成本函数和硬约束。适合当前程序拆分 QEM cost、feature legality、boundary filter。需要从当前简单 Mesh 结构升级到半边或至少构建半边视图。
VCG / MeshLab成熟三角网格处理高质量 QEM edge-collapse 简化、拓扑清理、曲率、网格质量工具。适合对比输出质量和学习工程细节。GPL 生态，需要注意许可证；直接嵌入商业动态库通常不合适。

对圆孔识别最实用的组合

当前 STL 路线下，优先参考 Mauhing/hole-detection-on-triangle-mesh，把 boundary loop 提取做稳；然后参考 PCL 或 pyRANSAC-3D 的 RANSAC 思路，对候选 loop 做 plane + circle/cylinder 鲁棒拟合；最后再把识别出的圆孔 loop 交给当前 preserveFeatureCurves 做硬约束和投影。若将来有 STEP/B-Rep 输入，再参考 BRepNet/UV-Net 做语义孔特征识别。

12当前实现的风险与后续增强点

  • C++ ABI：当前公共 API 暴露 std::vector、std::string、Eigen 类型，适合同编译器/同运行时的 C++ 项目。若要做跨语言 SDK，建议新增 C ABI 包装层。
  • 拓扑保护：当前有基础退化检查和重复面删除，但还不是完整工业拓扑证明。可继续增加 link condition、自交检测、边界环一致性检查。
  • 特征检测：当前主要靠边界、二面角和圆拟合。更复杂 CAD 模型可以引入 normal tensor、曲率、多尺度特征线方法。
  • 误差度量：当前没有严格 Hausdorff 误差界。若用于生产，需要增加误差界、属性保持、法线保持和材质/纹理属性迁移。

特征保护路线图

第一阶段已经实现。--preserve-feature-curves 默认使用 --feature-protection-mode primitive-curves：圆、近圆和椭圆 loop 保持硬保护，generic polygonal 与 dihedral crease 作为软成本/guard 输入，而不是自动硬锁。

严格旧行为仍可通过 --feature-protection-mode all-feature-edges 或 --protect-all-feature-edges 启用。SDK 也暴露 FeatureProtectionMode / LqFeatureProtectionMode，包含 none、circular-only、primitive-curves 和 all-feature-edges。

  • Mars wheel：all-feature-edges 停在 10974 面，feature rejection 为 468702；primitive-curves 达到 9066 面，feature rejection 为 31，generic rejection 为 0。
  • Differential gear：all-feature-edges 停在 2662 面，feature rejection 为 68993；primitive-curves 达到 1236 面，feature rejection 为 0。
  • Fandisk：两种模式都达到目标，但 generic feature rejection 从 513 降到 0。
