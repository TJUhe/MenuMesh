1. 学习路线与完成标准

C++ Mesh/QEMSimplifier -> PlainMesh 交换类型 -> C ABI opaque handles -> option/report size-aware 转换 -> exception -> status/error text -> CLI parsing/binding/dispatch -> install -> find_package -> consumer tests

同一个简化功能会经过不同边界。学习时要持续区分：数据所有权、错误传播、结构体版本、动态库导出、命令行字符串转换和算法本体。

完成标准：能从一个 C 或 CLI 调用一路跟到 C++ simplifier，并能说明每层负责的验证、转换、所有权和错误语义。

单元 0：公共 C++ API

ManuMesh.SimplificationNamespaceApiIsProjectScopedManuMesh.QEMSimplifierObjectStoresOptionsAndLatestReportManuMesh.QEMSimplifierCopiesPimplStateIndependently

断点QEMSimplifier 构造/copy、setOptions、simplify。

观察Pimpl 独立性、options 验证时机、lastReport 更新和自由函数/对象入口的命名空间。

单元 1：PlainMesh 交换类型

ManuMesh.PlainMeshRoundTripsWithoutEigenInExchangeTypeManuMesh.SimplifiesPlainMeshThroughEigenFreeEntryPoint

断点toPlainMesh、fromPlainMesh、simplifyPlainMesh。

观察顶点扁平数组、face index、texture coordinate 保留和转换失败。PlainMesh 用于减少公共交换类型对 Eigen 的暴露，不替代内部 Mesh。

单元 2：C ABI 句柄与调用者内存

CApiTest.CopiesMeshDataOnlyIntoCallerOwnedBuffersCApiTest.RejectsNonFiniteVertexCoordinatesWithoutReplacingMeshCApiTest.SavesBinaryStlWithStandardLayoutAndLoadsItBack

断点manumesh_context_create、manumesh_mesh_set_data、manumesh_mesh_copy_vertices、manumesh_load_mesh。

观察opaque handle 内部对象、先验证后替换、调用者 buffer capacity、context error。C API 不允许 C++ 异常穿过 ABI。

单元 3：size-aware ABI

CApiTest.AcceptsOlderTrailingSimplifyOptionsAbiStructCApiTest.DoesNotWritePastCallerSizedSimplifyReportCApiTest.SizeAwareInitializersRespectMinimumLegacyCurrentAndOversizedCapacitiesCApiLegacyInit.SymbolsStayWithinFirstPublishedV1Layouts

断点initializeAbiBuffer、initializeSimplifyOptions、option converter、fillSimplifyReport。

观察struct_size、caller capacity、minimum/legacy/current write size、尾字段是否存在。新增字段只能追加，读取与写入都必须受容量保护。

关键：“当前头文件能编译”不等于 ABI 兼容。这里专门验证旧调用者、小结构体和超大预留缓冲区。

单元 4：错误翻译

CApiTest.MapsInvalidSimplifyOptionsToInvalidArgumentStatusCApiTest.RejectsUninitializedSimplifyOptionsAbiStructMeshIo.MalformedObjVertexLineIsAnErrorWithLineNumber

断点fail、translateException、manumesh_context_last_error。

观察C++ exception type、映射后的 ManuMeshStatus、详细消息何时清除。成功调用应清理陈旧错误，失败必须保留可诊断文本。

单元 5：CLI 完整链

manumesh_cli_rejects_unknown_optionmanumesh_cli_feature_reportmanumesh_cli_quality_refinement

断点ManuMeshCli::run、argument parser、option binding、runRegisteredCommand、具体 command handler。

观察command scope、缺失值/非法数值、默认 option、输入输出路径、退出码。CLI 测试由 CTest 注册，不全是 gtest。

单元 6：安装后的 SDK consumer

sdk_consumer_examplesmanumesh_example_basic_simplifymanumesh_example_c_api_basic

路径sdk-install-local -> sdk-runtime-test -> sdk-consumer-test。

观察安装目录的 include/lib/bin、ManuMeshConfig.cmake、imported target、DLL 邻接、C/C++ consumer 的独立 configure/build/test。

完成标准consumer 只依赖安装产物，不从源码树偷用 private header 或 build-tree target。

4. SDK 完整闭环如何判断成功

阶段验证内容失败通常说明
configureVS2019 x64/v142、install rules、package configCMake 导出或依赖配置错误
sdk-install-local头文件、库、DLL、CLI、props、CMake config安装规则不完整
sdk-runtime-test隔离 PATH 下 CLI 可启动运行时 DLL 或安装布局错误
sdk-consumer-test独立 C/C++ 工程 find_package、链接并执行公开接口、导出符号或 transitive dependency 错误
ctest presetSDK 用例与主回归一起执行发布配置与开发配置行为不一致
